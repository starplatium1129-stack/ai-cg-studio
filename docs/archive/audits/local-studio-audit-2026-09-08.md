## 【严重问题】

本轮没有证据将问题定为整站不可启动的 P0。以下属于可能遗失任务、结果或使工作台无法继续生成的 P1 问题。

| 编号 | 问题、触发条件与影响 | 已实施修复 | 验证 |
| --- | --- | --- | --- |
| P1-01 | 重启遗留任务清理将队列第 4 项当作客户端字符串，而实际为对象，导致旧任务识别失效；若仅修正位置，30 秒重扫又可能误删新任务 | 读取 `extra_data.client_id`；每个进程写入独立 `aics_session_id`，跳过本次新任务；按引擎区分稳定客户端 ID | 新增真实 HTTP 假上游测试，验证只取消旧任务、保留新任务和其他客户端任务 |
| P1-02 | 串行队列取消只减少 pending，闭包与 Promise 链仍留在被阻塞的队首后；反复入队取消可积累内存，调用者也无法立即收到取消 | 改为可移除的 FIFO 条目，取消时立即移出并拒绝 Promise，保持总在途容量与失败隔离 | 队首阻塞时连续取消 100 次，验证无积压且不执行已取消任务；既有 FIFO 测试通过 |
| P1-03 | 生成中切换引擎后，轮询、取消和卸载清理使用当前引擎，可能查错接口而留下 GPU 任务 | 冻结任务提交时的引擎；过期提交响应不得恢复界面状态，并尝试定向取消；提交 HTTP 连接提前关闭时取消已登记任务 | 新增切换引擎与卸载后延迟响应测试 |
| P1-04 | 网关关闭期间返回的历史或图片结果可能继续写入任务；终态计时未固定，进度订阅留到回收时才释放 | 异步边界检查服务关闭和任务状态，终态记录 `finishedAt` 并解除订阅，关闭后拒绝创建任务；超时请求定向取消 | 生命周期/路由套件通过；计时改为整数秒 |
| P1-05 | 首次下载结束便删除结果；HTTP 发送完成不代表浏览器已成功持久化，断线后无法重新取图 | 下载不自动消费；在现有任务 TTL 内支持重取，显式删除和 TTL 回收仍会清理文件 | 接口测试验证重复下载字节相同、显式删除后 404、TTL 回收；真实图片亦复验重取 |
| P1-06 | 必需角色 JSON 根结构错误被转换为空列表并缓存为成功；角色重复 ID 可造成选择与绑定异常 | 必需数据容器校验；角色档案与场景分片检查非空 ID、重复 ID；失败保留旧值并允许重试 | 新增损坏容器、重复 ID、修复后重试测试；297 个前端测试通过 |
| P1-07 | 模型目录查找使用普通对象索引，`constructor`、`__proto__` 等非模型名称可命中原型，继而造成异常 | 模型、LoRA、风格 LoRA 和角色均检查字符串类型与自有键 | HTTP 回归确认非法模型键均返回 400 |
| P1-08 | 图片临时写入在清理 try 块之外；磁盘满/权限错误可能留下临时文件，并被当成网络错误重复重试 | 写入纳入清理区间；明确磁盘与权限错误 `RESULT_SAVE_FAILED`，立即结束重试并给出可执行提示 | 媒体与接口契约通过；未在真实磁盘上制造满盘 |

## 【体验优化】

| 编号 | 发现 | 实现 |
| --- | --- | --- |
| E-01 | ComfyUI 执行异常被压成“上游暂不可用”，前端无法识别显存不足 | 从 history 的 execution_error 提取有界异常类型与信息，进入已有中文错误分类器；提交错误保留上游原因 |
| E-02 | 短暂网络中断/状态读取超时使界面直接失败，但 GPU 还在工作 | 在现有总截止时间内继续读取同一任务，显示重连提示，绝不自动重复提交；取消请求失败时继续确认状态 |
| E-03 | 任意可用底模使状态显示在线，但当前选定底模未安装 | 在线状态进一步要求当前模型可用，初始回落优先选可用模型 |
| E-04 | 二进制预览帧被当作文本转码并解析 JSON，徒增分配 | WebSocket 进度桥直接跳过二进制帧；取消中不覆盖进度文案 |
| E-05 | 非 JSON 的 404/405 响应丢失 HTTP 状态，导致旧接口取消兼容分支失效 | JSON 解析失败也保留 upstreamStatus；新增 404 文本响应回归 |
| E-06 | Anima 高清开关在两个位置重复，且“2×=4K”“TeaCache 2.4×”不是所有输入都成立 | 专家参数面板统一高清开关；展示预计输出宽高，去掉固定速度/4K承诺；其他输出按钮同步改准确文案 |
| E-07 | 启动脚本写死路径，并声称运行已过期的版本组合 | 路径服从 AI_WORKSPACE_ROOT，默认相对项目定位；启动时打印实际 torch/comfy-aimdo 版本 |
| E-08 | WD14 无法加载 | 备份并移除外部 pysssss.json 的 UTF-8 BOM；安装 onnxruntime 1.29.0 及所需依赖，重启后日志确认 WD14 加载成功。首次官方源超时，清华 PyPI 镜像重试成功 |

WD14 变更发生在本机 ComfyUI 环境，不属于本仓库 Git 文件。原 JSON 备份为 `runtime/wd14-pysssss-original.json`；安装和启动证据见本轮 runtime 日志。使用 CPU ONNX 提供者作为可用后备，不代表已经完成反推模型下载或 WD14 图片推理验收。

## 收尾修复与验收边界

- **场景门禁统一到实际编译链路。** 原始 negative 是场景排除项，工作台还会补齐全局保护词；检索 tags 不自动进入 Prompt。新增 scene-render-contract 复用真实模板过滤和负向组装。未知镜头仍有冲突时测试继续报错，不能靠复用编译逻辑掩盖真实缺陷。
- **优化器门禁检查原始持久化数据。** 不再先把数据在内存里修正再检查，也不要求把可选格式化建议全部写回。现有 5 条可机械规范化建议不是出图错误，没有执行这些改写。分级脚本只调整元数据，停止顺带改写 negative。
- **数据精确变更。** 11 条 All → R15 保守分级修正、相应使用标签、sc306 的使用标签整理、sc223 日文「见」→「見」。相对本轮基线 d49df9cb，302 条记录的 prompt/negative/animaCaption/recommendedSize 均未改变；100 条定稿基线完整通过。变更字段清单保存在 runtime/closeout-data-changes.json。
- **POV 与景别同时生效。** 原先 POV 优先后，明确写着“特写”的 camera 无法过滤 full_body。新增 sceneFraming，让角度选择保留的同时，模板按明确景别过滤；已做编译 token 检查、SFW 真实出图和正反回归。
- **真实窄屏遮挡修复。** 基础模式左栏原本跨两行，在手机/平板与画布重叠；900px 以下取消跨行。补齐深浅主题、基础模式截图与真实点击回归。
- **角色切换竞态修复。** 热门 → 工作室时先暂停可生成状态，等新的模型与 LoRA 列表返回再恢复，避免按钮已可点而配置仍为空。实际点击回归通过。
- **Windows 清理失败从源头解决。** 测试 Git 仓库初始化禁用无用的符号链接探测，避免留下 Node 无法删除的重解析点；13 项卫生契约测试全部通过，未吞掉清理错误。
- **旧测试适配实际组件。** 标题检查跟随 ControlIntro；样式检查区分 Vue scoped 样式与全局 CSS；浏览器用例显式切换素材/参数页签，使用当前角色目录、按钮和默认 MiaoMiao 模型。

没有进行全角色出图、长时间显存压力测试或所有可选 ComfyUI 节点推理验收；这些不作为本轮已完成项目。WD14 已能加载，不等于全部反推模型已下载。

本轮不夹带其他会话的 deploy-desktop-quick.ps1 改动。桌面同步已调用唯一入口 deploy-desktop.bat -SkipBuild；安装目录 routes/server/services/scripts/lib/data/dist 共 1309 个文件与交付源一致。桌面网关 3123 在线，onnxruntime-node 与 sharp 实际加载成功；安装版 Anima 真实出图 9 秒完成，重复下载字节一致。证据：runtime/closeout-desktop-verification.json、runtime/closeout-desktop-render.log、runtime/desktop-audit-render.png。
