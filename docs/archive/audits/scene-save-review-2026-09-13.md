# 场景保存提交复审（2026-09-13）

审计对象：最新文档提交 `80b434c` 及对应实现 `21b0f10`。本轮仅修复保存与读取的工程行为，没有编辑生产人物、场景、蓝图或图像提示词，也未调用模型、安装或发布。

## 结论

增量分片、退役 ID 与读取基线的方向合理，代码已有路由/写入模块边界和隔离测试。但初版测试偏正常顺序操作，遗漏了文件形态转换、同页多次新增、源产物漂移以及回滚范围，不能仅凭原测试通过认定并发与恢复可靠。

| 问题 | 触发与影响 | 本轮修复 |
| --- | --- | --- |
| P1：本地草稿 ID 重复 | 服务端候选号未预留；保存到项目之前连续复制领取同一 ID | 候选号作为下界，结合当前草稿与会话预留集合分配；状态不可用不猜号 |
| P1：内容与基线错配 | 先加载旧产物再请求当前版本；旧内容可能携带新版本覆盖 | 一次响应读取源快照与维护版本；版本包含源分片、退役清单及相关产物 |
| P1：规范化结果被旧草稿覆盖 | 保存后维护脚本调整内容，但前端只采纳新版本 | 成功回执带实际快照；无后续编辑则回填，有新编辑则保留草稿和旧基线并提示合并 |
| P1：升批后位置索引失效 | 单文件改为 `.1.json` 后，同次保存改/移/删旧场景仍访问旧文件 | 同步迁移位置与归属索引 |
| P1：失败恢复不完整 | 新分片及浏览器产物未纳入原快照 | 恢复所有受影响产物和源码版本；撤销新增源分片 |
| P1：CLI 可写出截断数据 | 缺号使读取提前结束，维护脚本继续增量写出 | 完整性校验下沉公共写入入口，异常时落盘前拒绝 |
| P1：损坏退役清单被当成空集合 | 解析和结构错误被吞掉，可能复用退役身份 | 仅文件不存在视为空，其他错误阻止操作 |
| P2：孤立批次与非法清单漏检 | 单文件和 `.2` 并存却无 `.1`，或存在非法批号/路径/重复声明 | 校验全部物理批次与声明；相邻编号比较避免巨大批号长循环 |
| P2：容量满阻断旧场景维护 | sc999 后状态端点报错，无法取得编辑基线 | 仍返回内容和版本，`nextSceneId:null` 单独表示不能新增 |

状态读取、保存、维护任务和保存失败回滚共用同一网关内的保存锁。冲突提示要求先导出草稿；重新读取前确认丢弃，避免无准备丢掉修改。

- 源写入隔离回归：24 例通过。新增升批、孤立文件、损坏清单、非法清单和公共入口测试先复现失败，修复后通过。

- 前端三份定向 Vitest：9 例通过，覆盖唯一 ID、快照读取、保存中编辑保留和规范化回填。
- 后端/API/分片/维护帮助函数/单体预算合计 69 例通过；应用类型检查、受影响文件 ESLint（0 错误，3 条既有 v-html 警告）、双主题对比度与文档链接通过。
- 独立 Vite 浏览器回归 6 例通过：1440/1280/1024 布局、双主题、安装版只读模拟、连续复制与取消重读保稿、规范化回填。后续保留角色/样张元数据加载后，另通过 2560×1440 CSS 视口、deviceScaleFactor 1.5 的深浅主题 2 例，并逐图查看截图。该环境不等于原生 WebView2 实机验收。
- 浏览器使用只读 JSON 夹具，维护写请求默认拦截，仅保存案例返回模拟成功快照；没有连接生产网关。相关 flows 成功回执夹具更新了 version/snapshot，但未重跑整个 flows 套件。

截图在 `test-results/scene-audit/` 的 light-2560/dark-2560 对应测试目录；临时测试配置在被忽略的 `scripts/archive/`，不作为新增维护入口。原有提示词研究改动一同交付，本次未部署。

这是单进程保护，不是跨网关/CLI/编辑器进程的文件锁协议；维护仍遵守单一写入者边界。没有实现自动合并、真正的服务端 ID 预留、单条变更集或 sc999 之后迁移。失败回滚是受控异常恢复，不是断电恢复。研究、真实模型出图与主力机验收不因本次测试通过而变为完成。
