## 结论与移植质量

按工程完整度评价，现有移植约 **8/10**。模型导入、作者动作、角色特有参数、浏览器与原生后端边界、桌宠窗口管理都有针对性的适配，值得保留。主要薄弱处在资源占用、隐藏状态与异步调度，而非需要推翻模型移植。这个分数是代码和本次浏览器验证的工程判断，不是对源 Live2DViewerEX 画面或 Windows 原生渲染逐像素一致性的认证。

本次复核保留了以下关键适配：

- 夏目贴图按数字顺序导入并保持 atlas 索引，作者 moc3、物理、41 个动作引用及动作变体继续使用。没有把叠层参数误当成多套衣装；宁宁的 expression 仍承担换装。
- 口型保持宁宁 `ParamMouthOpenY × 1`、夏目 `ParamMouthForm3 × -0.5`；夏目双眼继续使用 `ParamEyeLOpen` / `ParamEyeLOpen2`。叠层隐藏态继续区分 `0` 与 `-1`，作者动作期间保持参数所有权，结束后平滑回落。
- 原生 renderer 的 UV、预乘透明度、遮罩、固定内容边界和两倍超采样没有重写。桌宠 overlay 跟随、作者 HitArea、设备丢失通知，以及销毁模型后保留线程供重用的契约仍在。

**资源保全检查：117 个文件、70,145,092 字节与修复前 main 逐文件完全一致。** 当前资产与基线的 SHA-256 清单保存在本地原始证据中。历史维护记录记载了源 LPK 一致性检查；本机两个已知解包目录均不存在，因此这次没有重新证明“与源 LPK 完全一致”。

## 已实施修复

### 浏览器模型时钟与显示状态

浏览器模型改由所属应用的 ticker 驱动，取消独立共享 ticker 的自动更新。隐藏时同时停止模型计时、渲染、情绪和目光循环；恢复时限制单帧时间步长，避免长时间隐藏后的跳变。暂停单个模型不会停止另一个模型。减少动态效果时保留首次静态帧。

模型首次就绪就应用帧率，不再依赖换装分支。夏目的单衣装提前返回不再导致无限帧率。桌宠区分显式窗口可见性与透明 WebView 的 `document.hidden`，布局、语音唤醒和恢复不能重新显示被隐藏的原生 overlay。

### 桌宠消息与原生帧间隔

口型、情绪消息采用一个在途请求与一个最新待发值，稳定值去重，口型最终归零优先发送。隐藏时清除陈旧采样，目光消息也受可见性限制。帧参数和 FPS 的已有去重逻辑继续保留。

原生隐藏窗口使用最长 100 ms 的消息等待；新命令可立即唤醒。活动帧等待扣除本帧工作时间。设备丢失检查和退出处理保留。前端保留接电原生目标 165 FPS、电池 30 FPS、浏览器 60 FPS；这不是本机测得的原生持续帧率。

启动 `getState()` 的迟到响应不能覆盖期间收到的可见性、电源和窗口边界事件。旧版桌面桥不支持纹理档位时继续原始画质，并禁用对应选项。

### 可选画质与音量

房间与桌宠设置新增画质选项。**默认仍为原始高清**；标准档将宽高各减半，节能档各减为四分之一。切换会重载模型并保留换装偏好；偏好可跨窗口同步并纳入备份键白名单。

浏览器使用服务端派生纹理，原生代码在上传纹理前按同一档位调整尺寸。派生服务限制角色、档位、索引和真实文件路径，保留纹理顺序与模型其他引用；同一转换合并请求，串行处理，内存缓存上限 32 MiB，按源文件大小和修改时间失效。重采样后使用无损 WebP 编码，不覆盖原图。

互动音效跟随房间音量，静音和说话期间不另起互动音效。修复音量 `0` 保存后错误恢复为 `80` 的问题。

## 本次实际测量

六组真实浏览器模型加载均通过：两位角色 × 原始 / 标准 / 节能。每组初始化上限均为 60 FPS；模拟页面隐藏后的 1,100 ms 内，原始模型更新计数和参数更新计数均为 **0**，恢复后 300 ms 内重新产生 17–18 次模型更新，没有页面异常。修复前同口径样本在隐藏期间仍有约 160 次模型计时回调；该差异不能直接换算成 CPU 百分比。

| 角色 | 档位 | 纹理文件传输量 | 基础 RGBA 纹理容量 |
| --- | --- | ---: | ---: |
| 宁宁 | 原始 | 42.85 MiB | 256 MiB |
| 宁宁 | 标准 | 3.24 MiB | 64 MiB |
| 宁宁 | 节能 | 1.17 MiB | 16 MiB |
| 夏目 | 原始 | 8.08 MiB | 896 MiB |
| 夏目 | 标准 | 10.27 MiB | 224 MiB |
| 夏目 | 节能 | 3.97 MiB | 56 MiB |

传输量来自实际资源字节数。RGBA 容量由浏览器实际加载的纹理宽高 × 4 求和，**不是实测显存、总进程内存或峰值**，不含 mipmap、遮罩、超采样缓冲及其他开销。原生仍需解码原始图片，低档位不能消除首次解码峰值。夏目原有 WebP 压缩率较高，标准档派生文件反而略大，因此标准档主要节省渲染内存，不保证下载更小。首次派生转换也需要 CPU 时间。

实际点击“节能 → 标准”后，宁宁纹理恢复至 4096 × 4096，只有一个 canvas，校服选择保留，偏好正确落盘。截图复核没有发现明显 atlas 错位、缺层或透明边缘异常；重采样后的细节变化不能视作原始画质完全等价。

运行库保持按需加载：`wl-live2d` 独立懒块 **945,579 字节**，gzip 262,057 字节，Brotli 211,390 字节。它本身预捆绑 Pixi/Cubism；这次没有更换运行库或宣称已经缩小该块。

当前工作台路由 JS **123,214 字节**、CSS **102,640 字节**，静态依赖闭包 **537,203 字节**。闭包较基线增加 2,922 字节，仍低于 580 KiB 硬预算，但超过其 90% 提醒线；Live2D 懒块也仍有 90% 提醒。所有预算保持原值，未通过改阈值消除提醒。

## 验收与证据

最终代码执行 `AICS_REFERENCE_AUDIT_MODE=structure npm run workflow -- gate:full --verbose` 通过：22 步质量检查、应用和运行时类型检查、85 个文件的 607 项前端测试、474 项 Node 单元测试、25 组接口契约及生产构建。Node 套件共 475 项，其中真实样张资产检查因办公机没有 `AI/SceneShowcase` 而跳过 1 项，没有将其计为通过。结构模式不代表真实角色参考图或 AI 出图验收。

首次全站关键浏览器回归为 310/312 通过。两项失败已定位：销毁前误绘制首帧启动异步 idle，随后访问已释放的动作队列；控制页轮询没有等待请求完成，慢响应被每隔三秒的新请求取消。前者改为仅在明确请求减少动态效果时绘制静态首帧，后者等待状态和日志请求完成；同步修正了旧契约中“每隔三秒取消旧请求”的断言，仍保留停止/卸载取消与主动请求替换的检查。快速角色切换和深浅主题保存重试连续三轮 9/9 通过；最终全站浏览器复验 **312/312 通过，0 失败、0 跳过、0 flaky，无重试**。首次失败的 trace 与日志保留，未将复验结果覆盖成首轮全通过。

新增两个原生桥模拟浏览器用例已通过，覆盖启动事件竞态、隐藏 / 恢复、电池帧率、非活动 WebView 和旧桥兼容。原生帧间隔纯 Rust 模块独立编译后 6 项测试通过。纹理服务 5 项测试实际生成小图并发起 HTTP 请求，覆盖透明通道、缓存与失效、失败重试、路径拒绝和 ETag 304。

原生代码检查也已完成：复用了主工作区已有的 `runtime/desktop-build-sdk/CubismSdkForNative-5-r.5`，显式设置 SDK 路径并使用隔离编译输出，执行 `cargo check --tests --locked --offline --manifest-path desktop-tauri/src-tauri/Cargo.toml`，退出码 0。该检查覆盖 Tauri/Rust 源码和测试的类型检查，并实际编译 Cubism C++ 桥；没有生成或运行原生应用，也没有将仅编译的 Rust 测试计为已执行。最初隔离 worktree 未发现 SDK 的结论已由本次实际检查更正，没有下载或安装 SDK。

四组小屏 UI 检查覆盖房间 390 × 844、桌宠 360 × 520 的深浅主题；画质控制无横向溢出，标签和选项文字实测对比度最低 8.71:1。另复核桌宠 360 / 480 宽度截图。

## 明确未验收的部分

本次完成原生源码、测试类型检查和 Cubism C++ 编译；**尚未完成原生可执行程序的完整链接和运行验收**。真实 overlay 渲染、原生画质切换、实际显存 / CPU 测量、多显示器 DPI、休眠唤醒及真实 TTS 联动仍未验收。原生代码检查、已执行的 6 项纯 Rust 测试和桥模拟测试不能替代这些项目。

没有进行 AI 后端出图、模型下载、桌面安装或部署。后续主力机验收应使用现有原生验收入口，重点复查两位角色的动作 / 换装 / 叠层回落、三档纹理、窗口跟随及隐藏恢复；源解包资源可用时再进行本次源文件一致性复核。
