## 批量出图修复

| 发现 | 实际改动 |
| --- | --- |
| 等整批结束才进入结果页，任务对象修改不触发及时反馈 | 启动立即显示进度，通过响应式任务数组更新逐张状态 |
| 取消全选在循环中重新判断，导致只取消一部分 | 固定本次操作方向；“全选匹配项”覆盖所有筛选结果 |
| 已选数量包含隐藏项，提交却只提交当前筛选内的项目 | 按完整已选集合提交；搜索后已选项目不会悄悄丢失 |
| 上千蓝图、上百角色同时铺满列表 | 首屏 30 项，按需增加；场景支持按角色名称搜索并显示归属 |
| 关闭运行面板后无法再打开 | 提供“查看批量进度”；关闭面板继续执行，离页仍走已有确认并停止后续任务 |
| 停止被说成“全部入册”，未开始的任务显示错误文案 | 单独显示成功、失败、未执行；等待停止状态和重试数量明确 |
| 重跑时重新读页面参数，甚至将作品名当成提示词 | 固定原始素材、所选引擎的种子、模型、引擎和批次参数；重试不重建素材 |
| 蓝图只拼散文和当前角色，未用服装、镜头、尺寸及负向编译 | 热门蓝图走标准编译器，使用蓝图自己的角色、outfitId、镜头、尺寸和 negative；分级授权不满足则拒绝 |
| 热门目标误带工作室 LoRA 或 SD 路线 | 热门目标使用 Anima/Krea 路线并清除工作室 LoRA；SD 仅供工作室目标 |
| 入册失败仍显示成功，重试重复生成 | 保存返回值确认成功后才计入成功；保存失败保留图片，重试只保存已有图片 |
| 满队列导致逐项立即失败 | 对明确拒收的 HTTP 429 等待空位，最长两分钟；可停止等待；不重提已接收的任务 |
| 状态读取短暂断网即失败并继续提交后续图 | 重连同一任务；等待超时仅尝试停止该已知任务，不清空公共队列 |

批量仍为逐张串行，停止默认等待当前已接收的图完成。没有新增同时向显卡倾倒大量任务的并发模式。

## 反推冲突修复

- 服装、时段、天气按类别判断，修复“校服阻止白天”“夜间误触发泳装替换”。
- 场景实际提示词、已有手动词条、已接受的反推词条均参与检查；搜索索引 tags 不冒充编译词条。
- 归一后去重，同一批重复返回的标签不会被 toggle 操作再次删掉。
- 已知身份域按当前角色优先；solo 与单人兼容，双人/其他数量冲突继续拒绝。
- 明确景别优先，拒绝特写与全身等已知冲突。
- 同一反推结果出现多套互斥服装时保留优先家族；同家族的 swimsuit/bikini 保留在一起。
- 服装替换同时清掉旧手动服装家族；上下文读取正在生效的换装，角色别名参与同角色判断。
- 工作室场景不能整体替换场景服装时明确拒绝冲突，不再静默丢掉服装词。
- 自然语言 caption 明示仍需核对语义；本轮没有假称能自动解决任意散文里的身份和服装冲突。
