结论

七维均值 6.8 / 10——能力层明显强于接线层。

这个项目的 UX 基础设施建得比大多数同类项目都好：Comfy 步骤级进度、真实取消（前端 abort + 后端 interrupt）、十类错误分类与恢复动作、LRU 大图内存工程、8 类深链参数、焦点陷阱、指针事件全量统一、破坏性确认默认聚焦取消。这些都不是敷衍实现，是读过规范后的产物。

问题是这些基建没有接通到用户最高频的那条路径上：步骤级进度只接在 Anima 面板，主出图路由 comfy-progress 引用数为 0；真实取消接成了「切页即静默取消」，没有离开守卫；错误分类器只被 2 处调用，Anima / 视频 / 反推仍在直出英文技术串。水管四通八达，主出水口是堵的。

9 条 P0 里 6 条是单点改动（S 级）：一条 filter 写反、一个 Enter 分支、一处 patch 条件、一个默认开关值。它们的共同点是——不是没做，是做完了没接上，或者接反了。全部修完预计不超过 3 小时，均值可到 7.8+。

P0-1确认框里按 Enter 会执行删除，而不是焦点所在的「取消」ConfirmDialog.vue:84 · S

证据：onKeydown 里 else if (e.key === 'Enter') { e.preventDefault(); ok() }。document 级 keydown 抢在按钮原生激活之前 preventDefault() 再调 ok()，导致焦点在「取消」上按 Enter 仍然确认。与同文件 :72 的注释「破坏性操作默认聚焦取消键，Enter 手滑不会直接执行删除」直接矛盾——这正是项目红线里点名的「注释与代码矛盾」高危项。

影响：清空全部本地对话、删除历史作品、覆盖式恢复——这三件事的最后一道防线形同虚设。一次手滑 = 不可撤销丢数据。

function onKeydown(e: KeyboardEvent) {
  if (!state.value.visible) return
  if (e.key === 'Escape') { e.preventDefault(); cancel() }
-  else if (e.key === 'Enter') { e.preventDefault(); ok() }   // 删掉这一行
}

删掉后浏览器原生按钮语义生效：Enter 激活当前焦点按钮，而 danger 态已默认聚焦「取消」（:64）。Escape 分支保留。

整页刷新不是性能 bug，是 CSP 需要 unsafe-eval 给 Live2D 的必然代价——删掉它，从站内点进房间时 Live2D 必然初始化失败。420ms 遮罩是整页刷新期间盖白屏的动画，不是阻塞延迟，同样不动。能修的预热那一半已经修了。

不改sdParams.size

审计判为「无读取方的双份状态」，但它在 promptBuilderPersistence 里参与草稿序列化与恢复，是参数存档契约的一部分。删掉一个 UI 上没人读的字段，收益远小于破坏旧草稿兼容的风险。

暂缓body{overflow-x:hidden}

审计建议改 clip + 加开发态哨兵。这属于全局布局改动，收益是消除掩盖式兜底，但回归面覆盖全部 18 个路由，需要专门时间配合目测验证，不适合夹在这一批里顺手改。
