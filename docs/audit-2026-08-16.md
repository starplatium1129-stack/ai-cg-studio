## 一、安全面（最高优先级）

1. ✅ **desktop-tools `run_command` 任意命令执行（曾 Major，现修复）**
   - 现象：run_command 无命令白名单，模型工具调用可在本机执行任意系统可执行文件；
     remote 隧道访客也可置 `companionTools:true` 让共享 LLM 挂出工具 schema。
   - 修复：`routes/desktop-tools.js` 增加 `ALLOWED_COMMANDS` 白名单（python/python3/
     pythonw/pwsh/powershell/node/npm/npx/git/conda）或工作区内相对脚本（绝对路径/
     `..` 拒绝）；`routes/chat.js` 的 `companionTools` 仅 `isDirectLocalRequest` 放行。
   - 残留取舍：白名单解释器内的参数（如 `node -e`）仍由模型驱动，个人本地工具可接受；
     执行端本身仍 `localOnly`。

   （≤8 parts、≤4 张图、单图 data URL ≤12MB），AGENTS.md 措辞同步为「文本 24 条/12000 字

## 十一、第四批修复（2026-08-16 续，收尾三件）

1. ✅ **training 日志热路径同步 I/O 异步化（曾 Major）**：`consume` 原为每 chunk 同步
   `appendFileSync + statSync + readSync + writeFileSync`（4 次磁盘调用阻塞事件循环）。
   改为 `LogSink`（`services/training-service.ts`）：热路径只做内存追加；落盘按
   `LOG_FLUSH_DEBOUNCE_MS=50ms` 合并为异步批量写，缓冲 ≥`LOG_FORCE_FLUSH_BYTES=64KB`
   不等 debounce 立即落盘；截尾（超过 `logMaxBytes` 保留最近 75%，跳换行）在 flush
   周期内异步完成并 bump `logVersion`（运行中同步更新 progress.message）。
   `getLogs` 同步 → 异步（读前先 `flush()` 待写缓冲，轮询不丢尾巴；`nextCursor` 改用
   实际 `bytesRead`）；`routes/training.js` logsHandler 适配 Promise；close() 前
   `drainSync()` 同步兜底落盘剩余缓冲（关停路径一次性同步写可接受，保证不丢尾巴）。
2. ✅ **serial-queue pending+active 离一（cosmetic）**：判满从 `pending >= maxPending`
   改为 `pending + active >= maxPending`——此前队首任务转 active 后空出一个槽，实际
   在途可达 maxPending+1；合并计数后「上限」= 真实在途上限。新增 `cap-active` 用例
   （1 active + 2 pending 必须 QUEUE_FULL）。
3. ✅ **training close() 语义落地（观察项，2026-08-16 用户决策：kill）**：优雅关闭网关 =
   终止训练。close() 统一 `killProcess` 全部受管子进程（win32 为异步 taskkill spawn +
   unref，网关进程退出后仍会落地，不留孤儿 GPU 进程；子进程 close 事件驱动的状态回收
   照常）；不再保留「跨重启存活」（网关退出会关闭子进程 stdout 管道读端，存活训练下次
   打印大概率 BrokenPipeError 崩溃，等于半死状态——终止是唯一确定语义）。测试新增
   close 杀子进程 + drain 缓冲断言。
