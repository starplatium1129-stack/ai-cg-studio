# 005：PC 桌面架构整理与交接计划

> 2026-09-12；状态：已规划，尚未实施。总优先级见 [未来规划](../docs/roadmap.md)。

## 目标与执行边界

保留 Vue 3 / TypeScript / Pinia、Tauri / Rust、本地 Node / Express 网关及现有模型接入，降低工作台耦合、统一布局职责，让桌面端更易维护和验证。

- 用户主力环境：**4K（3840×2160），Windows 150% 缩放**。以约 2560×1440 逻辑空间为基准，同时检查任务栏占用和非最大化窗口。
- 默认不增加业务功能、不更换框架、不重写整个项目。手机只保留兼容兜底。
- 下一对话先执行阶段 0、A、B。阶段 C、D 先形成具体设计与隔离验证结果，再确定后续实现范围；不把数据库迁移或重启自动恢复混入纯重构。
- 不改提示词、蓝图、服装绑定、分级及远程接入边界，不触碰定稿基线和真实作品数据。
- 同步、安装、真实模型与设备验收遵循现有任务授权和 [工程契约](../docs/engineering-contracts.md)、[工作流](../docs/workflow.md)、[部署指南](../docs/desktop-deployment.md)。

## 已有基线与发现

基线提交：`321f983`（已推送 origin/main）。下次开工以实际 HEAD、git status 和 diff 为准，不覆盖后续会话改动。

已完成的 UI 优化不要重新设计：

- 首页最近作品前移、主视觉高度调整、列表和选中动效缩短。
- 桌面标题栏高度纳入工作台布局；1024px 起专家三栏；宽屏利用率提升。
- 专家模式场景列表填满素材栏剩余高度，筛选区与结果滚动分离。

最后一轮证据：24 项桌面布局回归通过，覆盖 4K 缩放、窗口尺寸、深浅主题、列表剩余高度、悬停稳定性、滚轮、显示更多和末尾访问。生产构建、样式与对比度检查通过。桌面桥接为测试模拟，**没有替代真实 WebView2、跨显示器、休眠或安装验收**；安装版尚未同步。

关键问题不是文件数量，而是职责：

1. 工作台布局在多个样式层重复声明；此前内层列表仍有 540px 限高，外层却已经随窗口拉高。
2. `usePromptWorkspace` 汇集素材、生成、结果及界面状态，子组件有直接依赖其完整返回类型的情况。
3. 作品索引与图片分别位于 IndexedDB，设置等还有独立存储；已有仓储、Web Locks 与补偿处理，不能重构时丢失。
4. 公共任务注册表使用内存 Map；仅这一层不足以保证网关重启恢复。引擎自己的取消与轮询语义有差异，不应机械合并。

## 阶段 A：整理桌面布局与滚动职责（第一优先级）

主要文件：`director/layout.css`、`workspace.css`、`expert-workspace.css`、相关组件样式、`DesktopTitleBar.vue`。

工作：

- 外层工作台负责可用空间和三栏分配；面板负责内部结构；内容列表负责自己的滚动。
- 用少量有明确含义的尺寸变量表达标题栏、导航和工作区留白，清理本次涉及元素的重复高度、旧限高与覆盖规则。
- 仅在内容确实不足以容纳时保留必要滚动嵌套，检查滚轮交接、键盘焦点和筛选位置。
- 保留最新视觉结果；先确认胜出的样式来自哪里，再删除旧规则，避免用更高选择器权重继续叠补丁。
- 专家、场景、专注模式分别验收；不能为了专家模式破坏基础模式或窄窗口。

验收：

- 4K 150% 深浅主题：列表没有无故留白；参数可读；生成按钮可达；无横向溢出。
- 最小 1024×720、常用笔记本和 4K 非最大化窗口保持合理布局。
- 场景、热门角色、历史等实际内容都检查，不能只验空画布或面板外框。
- 切换分类、改变筛选、加载更多、键盘定位后，不丢输入、选择和原有滚动行为。
- 受控区域形成明确的样式归属，删除已验证无用的旧规则，避免新增一套平行布局系统。

## 阶段 B：缩小工作台状态与组件接口（第二优先级）

主要文件：`usePromptWorkspace.ts`、`prompt/` 与 `scene/` 下相关 composable、`PromptMaterial*.vue`、必要的 store。

工作：

1. 按实际职责划分接口：素材选择、生成任务、结果处理、界面状态；复用已有模块，不按文件行数机械拆分。
2. 组件逐个改为只接收需要的数据和动作；移除子组件对完整 `ReturnType<typeof usePromptWorkspace>` 的依赖。
3. 每个业务状态保留唯一归属，其他模块通过派生值或明确动作访问，避免新增镜像 ref 和双向 watch 同步链。
4. 将适合的纯计算与编排副作用分离；保留 store、composable、组件之间原有响应性和生命周期。
5. 保持 `usePromptWorkspace` 为轻量组合入口；不把原来的大对象换个名称搬到新文件。

验收：

- 角色／场景选择、深链、草稿恢复、历史复用、模式切换和异步面板首次加载行为一致。
- 使用隔离上游检查提交、忙碌、取消、失败重试、结果保存；不触发真实模型。
- 既有生成请求的关键字段在重构前后保持一致；若确需改变编译或内容语义，停止把该变化归入纯重构，按项目真实出图约束处理。
- 窗口／路由切换没有重复订阅、重复轮询或悬挂回调。
- 类型检查与定向回归通过；没有以 `any`、大量类型断言、重复状态来掩盖边界问题。

## 阶段 C：桌面数据归属与持久化设计（先评估）

入口：`src/storage/artworkRepository.ts`、`artworkMutation.ts`、`settingsRepository.ts`、`useKVStore.ts`、`useImageStore.ts`、备份与桌面桥。

交付一份有结论的设计，比较：

- 保留 IndexedDB，继续完善现有仓储与备份。
- 本地服务统一持久化，评估 SQLite 元数据加文件目录的收益与成本。

必须明确：

- 谁是写入的唯一入口，桌面多窗口和保留的浏览器访问如何协调。
- 原图、缩略图、作品索引、项目关系、设置、聊天数据分别由谁管理；不默认一轮全部迁移。
- 元数据事务与文件写入不是同一事务，如何处理半完成、孤立文件、回收站和失败补偿。
- 迁移版本、幂等执行、可恢复中断、旧数据备份、失败回滚及旧版本兼容。
- 性能比较使用同机隔离夹具和明确数据规模，不预设 SQLite 必然更快。

验收：有推荐方案、排除其他方案的理由、隔离原型证据、迁移与回滚步骤。阶段 C 不操作真实用户库，不新增运行时依赖或自动执行生产迁移。

## 阶段 D：长任务恢复设计与原生验收（先区分行为变化）

入口：`server/job-runner.js`、生成／Anima／视频路由、任务中心、Tauri 生命周期与部署流程。

工作：

- 分清窗口关闭、界面重载、网关崩溃、模型服务断开、系统休眠等不同情况。
- 盘点哪些任务已有可追踪后端 ID，哪些任务只能明确标记中断，不虚报“可恢复”。
- 如设计持久任务日志，规定状态转换、后端对账、幂等键、取消意图、超时与清理规则。
- 保留各引擎取消／轮询差异。恢复时优先查询后端，不盲目重提交同一任务。
- “重启后自动继续生成”属于新增用户可见行为，单独列明，不作为纯架构重构默认开启。

验收：隔离故障注入覆盖重复恢复、取消与完成竞态、丢失响应及损坏日志；真实主力机验收另列完成状态。

## 验证与交付规则

- 复用已有证据，按实际改动选择检查；不因提交或新增测试文件就自动升级全量。
- A：样式／对比度检查、桌面布局及双主题视觉检查。
- B：类型、相关组件与状态测试、受影响的生成／保存／深链浏览器流程。
- 构建用于验证产物；浏览器验收前完成构建，期间不修改共享 dist。测试使用独立端口偏移与输出目录。
- 优先复用 `desktop-workspace-layout.spec.ts`、`experience-polish.spec.ts`、`ui-layout.spec.ts`、`workbench-loading.spec.ts`、`library-concurrency.spec.ts` 及相关单测；先读覆盖内容再选择。
- 每阶段单独可审核、可回退；仅暂存受控文件，提交后 push。禁止整仓暂存和覆盖其他会话改动。
- 本计划记录进度即可，不为每个小修复再建一份重复审计报告。
- 部署仍只用 `deploy-desktop.bat`；有当前构建且无依赖／exe 变化可用 `-SkipBuild`。真实安装验收单列，UAC 由用户操作。
