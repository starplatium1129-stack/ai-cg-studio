# 绫季绘境：明日方舟式视觉语言与“众生行记”网页设计研究

> 文档性质：视觉研究与后续网页改造提案  
> 版本：v0.1  
> 调研日期：2026-07-30  
> 适用项目：AI-CG-Studio / 绫季绘境  
> 状态：提案，不直接覆盖 `DESIGN.md`

## 1. 目的

这份文档回答三个问题：

1. 《明日方舟》长期稳定的美术与 UI 语言到底由什么构成。
2. SideStory「众生行记」在这套基础上增加了哪些独特元素。
3. 怎样把这些方法翻译成绫季绘境自己的网页设计，而不是复制游戏皮肤。

目标不是让网站“看起来像明日方舟官网”，而是学习它处理以下矛盾的方式：

- 情绪化插画与理性信息系统同时存在。
- 高密度信息与明确操作层级同时存在。
- 活动主题变化很大，但基础品牌仍然可识别。
- 装饰、世界观和交互状态使用同一套视觉语法。

绫季绘境最终应形成自己的命名：

> **Atelier Archive / 绘境档案系统**

它表达的是“私人创作档案、导演终端和角色记忆”，不是罗德岛、拉特兰或 PRTS。

## 3. 核心结论

### 3.1 明日方舟不是一套固定皮肤

它更像一个稳定的“视觉语法系统”：

- 底层品牌语法负责信息纪律、工业感、层级和状态反馈。
- 每次活动再覆盖一层与故事地点、宗教、文化或技术有关的语义。
- 活动可以使用完全不同的配色、字体和材质，但编号、信息分层、画面焦点和交互逻辑仍然保持一致。

因此，不能把它简化为：

- 黑白灰；
- 黄色警戒条；
- 英文小字；
- 斜切矩形；
- 噪点和故障效果。

只复制这些表面元素，会得到一个“游戏风后台”，不会得到方舟式设计。

### 3.2 它的真正特征是高对比的信息编排

常见结构是：

1. 一幅承担情绪和世界观的主视觉。
2. 一组非常理性的编号、坐标、标尺、网格和说明。
3. 一个对比极强、位置明确的主操作。
4. 低权重但数量较多的辅助信息。

视觉焦点通常只有一个。其他元素再多，也通过透明度、尺寸、字重和锐度退到后方。

### 3.3 UI 装饰来自页面含义

优秀的装饰不是随机贴纸，而是当前系统的“证据”：

- 作战页面使用地图、路径、坐标和战术标识。
- 制造页面使用图纸、测量线、零件和工艺记录。
- 人物页面使用档案、编号、身份数据和摄影构图。
- 宗教主题使用圣像、比例、光环和仪式排版。

装饰同时承担世界观、分组或状态提示，极少只是为了填空。

## 4. 明日方舟的长期视觉语言

### 4.1 插画优先，但 UI 不退化成透明按钮

人物或场景插画通常占据最大的视觉面积。UI 不会平均铺满屏幕，而是集中在边缘、留白区和画面结构线附近。

值得借鉴：

- 先决定画面的主角，再找 UI 的位置。
- UI 面板顺着人物朝向、武器方向、建筑边缘或透视线布局。
- 背景先降对比、降饱和或失焦，再承载文字。
- 关键操作使用实色块或高锐度边框，不能淹没在插画中。

不适合照搬：

- 为了“沉浸”把所有控制做得过小。
- 在网页长文本、表单和参数区继续使用复杂插画底图。

### 4.2 极端但受控的层级对比

常见对比手段：

- 巨大标题与极小元数据并置。
- 高锐度文字覆盖在柔化、低对比的背景上。
- 纯黑或纯白信息块压住彩色插画。
- 一个高饱和信号色对抗大面积中性色。
- 粗线、细线、虚线和坐标线有明确等级。

网页落地原则：

- 每个屏幕只允许一个最高对比操作。
- 装饰文字不得和主要标题使用同等尺寸或字重。
- 状态色只表达状态，不把整页染成状态色。
- 对比要由尺寸、位置、锐度和材质共同完成，不能只依赖颜色。

### 4.3 工业印刷与临床档案

长期可见的元素包括：

- 网点、纸张颗粒、扫描噪声；
- 警戒斜纹、裁切线、套印偏差；
- 设备编号、坐标、日期、版本和单位；
- 黑白摄影、局部马赛克和失焦；
- 中英混排、窄体或 mono 元数据；
- 类似设备标签、药品包装或技术档案的文字结构。

这些元素共同产生“系统记录真实存在”的感觉。

绫季绘境可以将其翻译为：

- Scene 编号；
- Seed、Sampler、Checkpoint、LoRA 权重；
- 生成时间、审核状态、项目名；
- Prompt 结构版本；
- 角色、构图、光照和场景来源；
- 本机服务与存储状态。

也就是说，项目已经拥有大量真实元数据，不需要制造无意义的伪参数。

### 4.4 字体不是统一一种，而是按角色分工

常见分工：

- 中文无衬线：正文、操作、状态，保证小尺寸可读性。
- 中文或拉丁衬线：章节、宗教、历史或仪式性标题。
- 窄体、几何体或 mono：编号、时间、坐标、设备状态。
- 超大浅色文字：背景水印和空间分区。

项目落地：

- 正文继续使用现有 `--font-sans`。
- Scene ID、Seed、模型、端口和状态继续使用 `--font-mono`。
- `--font-serif` 只用于活动标题、角色档案引语和大幅叙事标题。
- 不引入《明日方舟》使用的专有字形或直接仿制其 Logo 字体。
- 首轮改造不新增网络字体，先用现有 Noto / HarmonyOS / JetBrains Mono 栈验证。

### 4.5 层叠、模糊和“仍然在同一张画布”

方舟常用以下方式降低页面割裂：

- 背景保留，弹出半透明或毛玻璃信息层。
- 主体轻微位移，为新信息腾出空间。
- 有逻辑关系的页面使用 zoom-in / zoom-out。
- 无直接关系的系统使用短促深色淡出。

适合绫季绘境的场景：

- 作品查看器覆盖作品册，而不是跳到完全不同的详情页。
- Prompt 健康、生成参数和错误恢复作为舞台上的次级层。
- 角色换装和 API 设置以抽屉或浮层出现，角色舞台保持可见。
- 场景卡进入绘制台时，图片和 Scene 编号可参与共享元素过渡。

## 5. “众生行记”的独特视觉层

### 5.1 主题公式：神性 × 理性 × 技术

官方主视觉把以下内容压在同一个画面中：

- 教堂、光环、飞升、手势等宗教意象；
- 坐标轴、圆规图、标尺、切线、几何构成；
- 人体比例、器官或机械结构的研究图式；
- 武器、工业制造和设备编号；
- 大面积圣洁白、冷蓝与少量炽热红橙。

其关键不是“宗教素材很多”，而是：

> 用数学和工程图的语言描述神性，用仪式和圣像的语言包装技术。

这正是该活动区别于普通工业 UI 的地方。

### 5.2 构图特征

#### 主视觉

- 人物集中在一侧，标题和几何图式集中在另一侧。
- 角色轮廓和飘带形成强方向线。
- 标题并非独立放置，而是与圆、轴、手势和建筑轮廓交叠。
- 画面有大量浅色留白，但留白中仍有低对比图纸纹理。

#### “制铳师之夜”

- 产品或物件像工业样本一样被单独展示。
- 圆形测量框、网格和切线围绕物件。
- 大标题压在对象与背景之间，形成印刷海报层次。
- 使用明确的物件视角，而不是平均展示整个场景。

#### “哄睡指标”

- 日期、活动路径、奖励星级、人物和说明被分成不同视觉带。
- 极粗的数字和星级负责远距离识别。
- 黑、白、蓝高对比块承担交互信息。
- 插画保持动态，但 UI 仍使用严格的水平、垂直轴约束。

### 5.3 色彩

推荐将“众生行记”归纳为以下角色，而不是逐像素采色：

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| Sacred Paper | `#F2F5F3` | 浅色档案底、主留白 |
| Archive Ink | `#11181D` | 主要文字、硬边面板 |
| Liturgical Blue | `#145BFF` | 主信号、进行中、选中 |
| Halo Cyan | `#79E7F2` | 光环、辅助标尺、柔和提示 |
| Graphite | `#667078` | 次级文本、测量线 |
| Ember | `#E65338` | 人物热源、危险、关键反差 |
| Veil White | `rgba(255,255,255,.72)` | 覆盖层与磨砂面 |

注意：

- 蓝色不能替代项目全部现有粉色。
- 宁宁的银紫、夏目的琥珀继续作为角色身份色。
- 蓝色更适合“档案系统、选中状态、生成进行中、技术测量”。
- 粉色继续负责“创作主操作、情绪和个人亲密感”。

### 5.4 图形语汇

可以原创转译：

- 同心圆、轨道、角度和十字准星；
- 画框裁切标；
- 坐标刻度、编号与连接线；
- 人物、场景或作品的测量轮廓；
- 图层注册点与印刷校准线；
- 光圈、声波、音量包络和时间轴；
- Scene → Prompt → Image 的结构图谱。

不要直接复制：

- 《明日方舟》Logo、周年标志或活动标志；
- 角色光环、专属徽记和组织符号；
- 官方活动中的手势图、维特鲁威式具体构图；
- 原活动标题的字形结构；
- 鹰角现有图标、按钮轮廓和界面截图。

## 6. 绫季绘境的原创转译

### 6.1 新设计概念

建议把网站的视觉叙事定义为：

> **一间安静的角色画室，外层接入一套严谨的创作档案系统。**

两种声音继续共存：

- **Atelier / 画室层**：角色、故事、情绪、作品、声音；温暖、亲密、柔和。
- **Archive / 档案层**：Scene、Prompt、模型、生成、审核、存储；精确、冷静、可追溯。

“众生行记”的理性与神性，在本项目中转换为：

- 神性 → 灵感、人物存在感、记忆和作品的珍贵性；
- 理性 → Scene 结构、参数、审核和生成链路；
- 技术 → 本机模型、SD、Ollama、TTS、Live2D 与 IndexedDB。

### 6.2 原创识别符号

项目可以形成自己的稳定符号：

- 双角色轨道：宁宁与夏目的两条偏心圆轨迹。
- Scene 标本框：把场景缩略图视为被记录、被审核的视觉标本。
- Prompt 光谱：用细线分解角色、场景、构图、光照和 LoRA。
- Generation Aperture：生成按钮或进度使用原创的光圈 / 快门结构。
- Memory Index：作品册以“记忆页码、日期、Seed”形成档案索引。
- Voice Envelope：配音使用真实音频包络，而不是通用声波图标。

这些符号必须源于项目数据或功能，不能只是背景装饰。

## 7. 设计 Token 增量提案

以下 Token 是研究阶段建议。实施前应合并进 `DESIGN.md`，再同步到 `src/assets/css/design-system.css`。

```css
:root {
  /* Archive semantic layer */
  --archive-paper: #f2f5f3;
  --archive-ink: #11181d;
  --archive-blue: #145bff;
  --archive-cyan: #79e7f2;
  --archive-graphite: #667078;
  --archive-ember: #e65338;

  --archive-grid: color-mix(in srgb, var(--archive-ink) 8%, transparent);
  --archive-line: color-mix(in srgb, var(--archive-ink) 18%, transparent);
  --archive-glass: rgba(245, 249, 248, 0.72);
  --archive-noise-opacity: 0.025;

  --r-terminal: 4px;
  --r-dossier: 8px;
  --line-hairline: 1px;
  --line-emphasis: 2px;
}
```

深色主题不应简单反相：

```css
[data-theme="dark"] {
  --archive-paper: #151b20;
  --archive-ink: #edf3f2;
  --archive-grid: rgba(220, 238, 240, 0.07);
  --archive-line: rgba(220, 238, 240, 0.18);
  --archive-glass: rgba(19, 25, 30, 0.76);
}
```

规则：

- 新色必须通过现有对比度检查。
- 不在 SFC 内散落硬编码色值。
- `archive-blue` 是档案和技术语义，不替代 `accent`。
- 角色色优先于档案蓝，避免宁宁和夏目被系统色吞没。

## 8. 材质与背景

### 8.1 网格

使用场景：

- 绘制台空画布；
- 训练台方案区；
- 控制面板状态区；
- 角色档案和作品详情的背景层。

规则：

- 线宽 1px。
- 常态透明度 5%–9%。
- 不直接穿过长段正文。
- 网格尺寸应来自布局尺度，例如 8px 或 24px，不使用随机间距。

### 8.2 纸张与噪点

可以使用一张项目自制的低对比无缝纹理：

- 256×256 或 512×512。
- WebP / AVIF。
- 页面常态透明度不高于 2.5%。
- 只覆盖大背景和大色块，不覆盖输入框文字。
- 关闭高对比模式或 `prefers-reduced-transparency` 时自动移除。

禁止：

- 高频动画噪点；
- 大面积胶片刮痕；
- 影响 CG 本身颜色判断的纹理；
- 每张卡片重复一套不同纹理。

### 8.3 模糊与磨砂

继续使用现有 glass token，但改变用途：

- 导航：轻度磨砂，保持环境连续。
- 作品查看器：深色半透明遮罩。
- 参数抽屉：较强磨砂，让画面仍可被感知。
- 普通信息卡：优先实色或近实色，不滥用玻璃。

## 9. 排版系统

### 9.1 页面标题模板

建议结构：

```text
03 / SCENE ARCHIVE
灵感场景
从角色的心情，走进一个可以生成的瞬间。
────────────────────────
```

其中：

- 编号：mono、12–13px、700。
- 英文 kicker：mono、11–12px、字距 0.08em。
- 中文标题：现有 display 栈、32–40px 桌面端。
- 简介：15–16px，最长 42 个中文字符。
- 分隔线：1px，不能代替真实分组间距。

### 9.2 大号背景文字

只适合：

- 首页 Hero；
- 章节入口；
- 空状态；
- 角色档案；
- 展示页开场。

规则：

- 透明度 3%–7%。
- 不作为唯一标题。
- 不与真实按钮重叠。
- 移动端隐藏或大幅缩小。

### 9.3 数据标签

统一格式：

```text
SC-263
SEED / 184927051
MODEL / WAI-ILLUSTRIOUS-SDXL-V170
STATUS / REVIEWED
```

中文负责解释，英文和 mono 负责索引。不要使用无意义的伪英文。

## 10. 形状与组件

### 10.1 卡片

把现有卡片分成两类：

#### Narrative Card / 叙事卡

- 8–16px 圆角；
- 允许温暖角色色和柔和阴影；
- 用于角色房间、最近创作、故事片段；
- 重点是人物与情绪。

#### Archive Plate / 档案板

- 0–8px 圆角；
- 1px 硬边；
- 左上角编号，右下角状态；
- 可有裁切线和测量标，但不超过两处；
- 用于 Scene、模型、训练、服务状态和生成参数。

同一分组中不要混用两套几何语言。

### 10.2 按钮

建议层级：

- Primary：实色 `accent` 或当前角色色；用于生成、继续、发送。
- Technical Primary：实色 `archive-blue`；用于连接、应用、启动、确认技术动作。
- Secondary：透明或浅底硬边。
- Ghost：文本加短线，只用于次要跳转。
- Danger：保留现有 danger，不改成蓝或粉。

按钮变化：

- 技术按钮圆角降到 4–8px。
- 叙事按钮可保留 8–12px。
- 主按钮可增加左侧编号或状态灯，但文字仍必须清楚。
- 不使用方舟式具体斜切轮廓。

### 10.3 标签与筛选

现有 pill 只保留给：

- 可移除筛选；
- All / R15 / R18；
- 角色筛选；
- 状态小标签。

分类导航和主要操作改为：

- 下划线；
- 侧边刻度；
- 矩形分段；
- 带编号的短标签。

避免全站所有组件都变成药丸形。

### 10.4 图标

后续应逐步替换主导航 Emoji：

- 使用项目原创的 1.5px–2px 线性图标。
- 图标形状来自镜头、档案、声波、画框、模型和服务节点。
- 图标必须配文字，关键动作不能只留图标。
- 不复刻明日方舟图标库。

---

## 11. 动效

### 11.1 页面关系决定动画

| 关系 | 动画 |
| --- | --- |
| 场景库 → 绘制台 | Scene 图片 / 编号共享元素，轻微放大进入 |
| 作品册 → 查看器 | 图片原位放大，背景降焦 |
| 角色档案 → 角色房间 | 角色色与立绘位置连续 |
| 普通页面切换 | 150–240ms 淡出 / 淡入 |
| 参数、设置、恢复动作 | 覆盖层或侧向抽屉 |
| 服务启动 | 状态灯、进度线和文字变化，不做装饰动画 |

### 11.2 动效边界

- 不增加常驻 glitch。
- 不让文字持续抖动、扫描或跳帧。
- 不给静态角色立绘添加周期位移。
- 只在真实数据变化时触发高亮。
- 遵守 `prefers-reduced-motion`。
- 所有共享元素过渡都必须有普通淡出的回退。

## 12. 页面改造映射

### 12.1 首页

目标：从“柔和入口页”升级为“私人创作档案的总封面”。

建议：

- 保留宁宁与夏目的主视觉。
- 左侧增加 `ATELIER RECORD / 00` 编号和细线构图。
- Hero 背景加入极淡场景网格、光圈和 Scene 路径。
- “故事 → 角色 → 场景 → 绘制 → 画面”变成真正的档案流程线。
- 最近创作采用相纸 / 接触印样结构。
- 主 CTA 仍使用粉色，不改成方舟蓝。

避免：

- 让首页变成黑色控制台。
- 在角色脸部覆盖坐标、文字或噪点。

### 12.2 灵感场景

目标：建立最强的 Archive 识别。

建议：

- Scene 卡突出 `SC-XXX`、审核状态、角色与评级。
- 缩略图像审核样本，而不是普通电商卡。
- 选中态使用蓝色测量框，收藏和角色色保持原语义。
- 过滤区使用横向刻度和编号分区。
- 分类切换时保持搜索与结果位置稳定。
- R18 模糊规则保持不变。

### 12.3 绘制台

目标：成为“导演终端”，但画面始终最大。

建议：

- 舞台使用低对比网格、构图安全框和生成光圈。
- 左右控制区使用 `01 STORY / 02 CHARACTER / 03 CAMERA` 编号。
- Prompt 健康、队列、恢复采用档案板而不是发光卡片。
- 当前模型、Seed、Sampler 在舞台边缘形成一条机器状态带。
- 场景模式只显示必要结构；专家模式再展开完整标尺和数据。
- 配音入口保持可见。

避免：

- 用复杂几何装饰缩小出图画布。
- 让所有参数默认展开。

### 12.4 角色房间

目标：保持亲密感，只让“系统层”变得更精确。

建议：

- 舞台和聊天气泡继续柔和。
- API、模型、Live2D 和配音状态改成细线终端条。
- 角色名字下增加 `ROOM / CHARACTER / VOICE` 档案索引。
- 换装控件使用“衣装档案”语义。
- 声音播放显示真实包络、当前语种和情绪 Profile。

避免：

- 把聊天气泡改成军事终端。
- 在角色立绘上叠加过多技术文字。

### 12.5 效果样张

目标：像经过审核的视觉证据墙。

建议：

- 首页统计改为审核批次、All / R15 / R18、最后更新。
- 卡片使用作品编号、审核章和固定元数据位置。
- 查看器可显示“身份 / 服装 / 肢体 / 构图 / 光照 / 叙事”审核维度。
- 审核章必须是项目原创，不使用官方印章造型。

### 12.6 作品册

目标：安静的私人摄影档案。

建议：

- 默认尽可能少显示 UI。
- 光标或键盘聚焦时才浮出 Seed、模型、评分和项目。
- 年月、角色、项目形成索引列。
- 图片仍按原比例展示，不为了档案排版强制裁切。

### 12.7 角色档案 / 画风 / 模型

目标：形成统一知识库。

建议：

- 左侧大视觉，右侧档案字段。
- 角色页使用角色色，不统一变蓝。
- 画风页用色谱、光照示意和图像样本。
- 模型页用训练版本、触发词、推荐权重和基线场景。
- 大段说明保持普通正文，不使用极小字号。

### 12.8 训练台

目标：最适合完整应用工业图纸语言的页面。

建议：

- 任务编号、阶段、数据集、输出和日志形成垂直流程。
- 参数区使用工程表格，不使用卡片瀑布。
- 运行中使用蓝色；成功使用绿色；警告和失败保持现有功能色。
- 日志只在需要时展开。
- 角色 LoRA 与角色语音继续保持独立所有权。

### 12.9 控制面板

目标：本机服务控制室。

建议：

- 常驻侧栏改成编号导航与服务总状态。
- 显存资源调度可用简化拓扑或资源条表达。
- 服务卡减少圆角和玻璃，改为实色状态板。
- 当前 URL、端口、Token 状态使用 mono。
- 分享入口保持明确警示，不因美术化削弱安全提示。

### 12.10 场景管理

目标：编辑和维护档案，而不是操作后台数据库。

建议：

- `场景库 / 标签库 / 样张 / 重复检测 / 导入 / 工具` 使用固定编号。
- 编辑区保持普通表单可读性。
- 验证结果使用审计报告样式。
- 待保存、备份成功、校验失败必须同时有文字和图形状态。

## 13. 桌面与移动端

### 13.1 桌面

- 保持现有约 1200px 正常内容宽度。
- 绘制台和控制面板可以使用更宽工作区，但不能无限铺满 4K。
- 允许非对称构图，但主要操作和阅读列必须稳定。
- 装饰可进入外侧留白，不得侵入表单和画面。

### 13.2 窄屏

- 装饰图层优先删除，不缩小后全部保留。
- 网格、背景大字、长测量线和角落编号可隐藏。
- 顶部导航回退为现有移动菜单。
- 页面顺序保持：主要内容 → 主要操作 → 次级设置。
- 禁止横向滚动。
- 触控目标至少 40px。

## 14. 无障碍与性能

### 无障碍

- 正文继续满足 WCAG AA。
- 蓝色不能作为唯一选中信号，需配边框、图标或文字。
- 极小 mono 文字只能是可忽略的元数据，不能承载关键操作。
- 网格和纹理必须位于文字下方，并可在高对比模式中关闭。
- 所有图形状态提供文本等价。
- 焦点环继续使用现有统一机制。

### 性能

- 无缝纹理总预算建议低于 80KB。
- 不使用视频背景。
- 不使用 Canvas 制造常驻噪点。
- 大型装饰图只在对应路由懒加载。
- Live2D 的按需加载约束不变。
- 动效优先使用 opacity 和 transform。

## 15. 实施顺序

### Phase 0：视觉验证，不改业务结构

1. 新建实验性 `archive` Token。
2. 制作一个页面标题模板。
3. 制作 `ArchivePlate`、`TechnicalStatusBar`、`SceneIndex` 三个原型。
4. 在截图或独立 Story 页面验证明暗主题。
5. 完成对比度、移动端和减少动态检查。

### Phase 1：低风险公共层

1. 页面标题和 kicker。
2. Scene 编号与元数据格式。
3. 导航 Emoji 替换为原创线性图标。
4. 统一分隔线、状态条和档案标签。
5. 样张与作品册的审核 / 存储元数据。

### Phase 2：核心页面

1. 灵感场景。
2. 首页。
3. 效果样张与作品册。
4. 角色档案、画风和模型。

### Phase 3：工作区

1. 绘制台舞台与参数层级。
2. 角色房间的 API / Voice / Live2D 状态层。
3. 训练台。
4. 控制面板和场景管理。

每一阶段都应独立通过项目质量门槛，不做一次性全站换肤。

## 16. 验收标准

一次改造只有同时满足以下条件才算成功：

### 视觉

- 第一眼仍能识别为绫季绘境，而不是明日方舟同人站。
- 人物与作品仍是主角。
- 档案蓝、角色色和粉色主操作之间职责清楚。
- 装饰来自真实项目数据或当前页面含义。
- 同一屏幕只有一个最高视觉焦点。

### 交互

- 新用户能在 5 秒内找到页面主要操作。
- 场景模式没有因视觉升级增加认知负担。
- 专家模式的信息密度提高但分组更清楚。
- 生成、队列、恢复和配音入口没有被隐藏。
- 移动端无横向滚动。

### 技术

- 颜色进入共享 Token。
- 没有新增业务 `any`。
- 无障碍对比度检查通过。
- `prefers-reduced-motion` 与 `prefers-reduced-transparency` 生效。
- 修改 `src/` 后通过 `npm run typecheck:app` 和 `npm run build`。
- 最终定向 Playwright 与完整 E2E 通过。

## 17. Do / Don’t

### Do

- 学习“语义决定装饰”。
- 用项目真实数据制造工业档案感。
- 用巨细对比建立层级，而不是让所有东西都更大。
- 让页面切换表达内容关系。
- 保持每个页面自己的叙事语气。
- 先做小范围原型，再升级公共设计系统。

### Don’t

- 不复制官方 Logo、徽记、按钮、图标或活动标题。
- 不把蓝白网格铺满所有页面。
- 不使用无意义坐标、乱码英文和伪科学参数。
- 不为了“方舟感”牺牲字号、可读性和触控面积。
- 不给所有卡片加斜切角、噪点和警戒条。
- 不把角色房间改成军事控制台。
- 不改变 R18 默认开启与缩略图模糊规则。
- 不删除配音、队列、错误恢复或 Live2D 按需加载。

## 18. 推荐的第一批设计原型

后续真正开始改造时，建议先做三个可比较原型：

1. **灵感场景 Header + 一张 SceneCard**  
   验证档案编号、图片、评级、角色色与蓝色选中态能否共存。

2. **绘制台空舞台 + 技术状态条**  
   验证网格、构图安全框、模型信息和主要生成按钮是否仍以画面为中心。

3. **角色房间舞台 + Voice 状态条**  
   验证工业信息层能否加入，同时不破坏角色的亲密氛围。

这三个原型分别覆盖：

- 内容发现；
- 核心生产；
- 角色体验。

只有三者都成立，才说明这套视觉语言适合全站。

## 19. 一句话设计准则

> **把每张 CG 当作珍贵的记忆，把每个生成步骤当作可以验证的档案。**

这是绫季绘境可以从《明日方舟》和「众生行记」中吸收、同时保持原创身份的核心。

## 20. 平面设计专项：让网站拥有“出版物感”

UI 解决的是“用户如何完成任务”，平面设计解决的是“用户如何记住这一页、如何感知主题，以及内容以什么节奏被观看”。两者必须分层处理：

- **功能层**负责导航、状态、表单、反馈和可访问性；
- **编排层**负责焦点、留白、图文关系、阅读顺序和情绪；
- **识别层**负责让首页、专题、场景、作品和角色档案形成同一系列；
- **内容层**始终以项目真实的 CG、角色、场景和生成数据为核心。

官方活动素材值得学习的不是某一个斜角、字体或警示条，而是“每个主题都拥有独立的视觉命题，同时又服从统一的信息秩序”。「众生行记」主视觉使用人物群像、巨大标题和细密信息形成尺度冲突；「制铳师之夜」把武器与零件组织成标本/技术图谱；「哄睡指标」则用集中人物、环形符号和条带信息建立另一套节奏。三者不同，但都能被识别为同一产品体系：

- [「众生行记」官方主视觉](https://web.hycdn.cn/staging/announce/images/20250425/8ff7e66c1ef9206ba79f0d86aa10d92f.jpg)
- [「制铳师之夜」官方视觉](https://web.hycdn.cn/staging/announce/images/20250425/d43eb90757447907894cf76006e449da.jpg)
- [「哄睡指标」官方视觉](https://web.hycdn.cn/staging/announce/images/20250425/78cf90c8e39b147db6e7091d0843ac28.jpg)

公开分析中反复出现的高层级差、背景模糊、衬线与无衬线/等宽字体分工、噪点与警示纹理，也可作为方法参考；但最终落地必须换成项目自己的内容语义，而不是复刻现成皮肤：

- [腾讯游戏学堂：明日方舟 UI/UX 分析](https://gameinstitute.qq.com/article/10027)
- [《我在明日方舟里面学平面设计》](https://zhuanlan.zhihu.com/p/145684354)

### 20.1 五层构图模型

每张专题头图、章节封面或重要空状态，先按以下五层搭建。顺序代表阅读优先级，不代表 DOM 顺序。

| 层 | 内容 | 任务 | 约束 |
|---|---|---|---|
| 1. 主体层 | 角色、CG、场景或关键物件 | 形成第一焦点 | 同一画面原则上只有一个主焦点 |
| 2. 标题层 | 中文主题名、章节名、关键数字 | 建立语气与尺度 | 标题不能压住脸、手和关键叙事物 |
| 3. 结构层 | 分栏、轴线、边框、遮色块、圆/方框 | 组织画面 | 每条线都应参与对齐或分组 |
| 4. 证据层 | 时间、模型、角色、seed、评级、编号 | 让装饰拥有真实含义 | 禁止虚构坐标、乱码和伪参数 |
| 5. 氛围层 | 网格、噪点、低对比水印、纸张/屏幕纹理 | 统一材质 | 不得降低正文和作品的可读性 |

执行原则：

- 先让第 1、2 层在灰度状态成立，再添加结构与材质；
- 任意一层删除后，主要任务仍应可完成；
- 每个构图只允许一个最高对比区；
- 装饰层统一 `aria-hidden="true"`，不可进入键盘焦点和读屏顺序；
- 原图查看器不叠加噪点、双色化或扫描线，处理仅用于封面、缩略图和专题包装。

### 20.2 网格与“受控破格”

平面感不来自随机错位，而来自先建立秩序，再有限度地打破秩序。

#### 基础网格

- 桌面端使用 **12 列网格**，列间距 20–24px；
- 收束内容宽度继续遵守现有约 1200px 基线；
- 8px 为普通布局基准，4px 用于细节校正；
- 重要构图轴优先落在 1/3、1/2、2/3 位置；
- 文字、图像边缘和元数据至少共享一条可辨认的对齐线；
- 工具页优先稳定网格，专题页才允许跨列、出血和局部越界。

#### 破格规则

可以破格：

- 人物轮廓越过标题色块；
- 大号章节数字延伸到内容外侧；
- 一条强调轴跨越多个分区；
- 图片在桌面端少量进入页面留白。

不可以破格：

- 关键按钮离开稳定操作区；
- 表单标签和输入项失去对齐；
- 文字压到人物面部或作品核心；
- 移动端保留桌面越界造成横向滚动；
- 为“看起来复杂”而制造无法解释的折线和坐标。

### 20.3 尺度对比与文字编舞

明日方舟式平面设计最值得学习的是**尺度关系**，不是简单地把所有标题变大。

建议建立五档视觉尺度：

| 角色 | 桌面建议 | 移动建议 | 用途 |
|---|---:|---:|---|
| Display | 56–88px | 38–52px | 首页、专题、章节分隔；一屏最多一个 |
| H1 | 36–48px | 30–38px | 普通页面标题 |
| H2 | 24–32px | 22–28px | 模块标题 |
| Body | 15–17px | 15–17px | 正文、表单、说明 |
| Meta | 10–12px | 11–12px | 可忽略的编号、时间和参数 |

编排规范：

- 中文承载主语义，英文只作分类、缩写和节奏辅助；
- 一个组件内最多出现三档字号；完整专题构图最多五档；
- 大字可以被裁切，但必须仍可识别，且需有完整可读标题作为语义备份；
- 字间距放宽只用于短标题、编号和标签，不用于中文正文；
- 等宽字体只用于模型、seed、分辨率、时间、队列和版本；
- 背景水印只能重复当前页面真实标题、章节号或对象名；
- 竖排只用于短章节字样或侧边索引，不能承载核心操作说明；
- 避免把无意义英文拆成数层当作“科技感”。

可使用的文字构图手法：

1. **巨型章节号 + 小型完整标题**：用数字建立远距离轮廓，用小标题保证阅读；
2. **标题压图**：标题色块进入图片，但避开脸、手和视觉动作线；
3. **边缘索引**：在外侧留白中放置当前章节、总数和浏览位置；
4. **背景水印**：低对比重复场景或角色名，只用于大面积安静背景；
5. **注释引线**：只指向真实的角色、构图特征或生成参数。

### 20.4 图像处理规范

CG 是项目最重要的资产。平面包装应该放大作品，而不是把所有作品强行滤成同一种颜色。

#### 三种图像角色

**A. 原作展示**

- 作品册大图、对比图和审核图保持原色；
- 不加颗粒、故障、扫描线和装饰边框；
- 可使用纯色背景与清晰 caption；
- R18 缩略图和样张继续遵守现有模糊遮罩。

**B. 专题封面**

- 可裁切、局部出血、前景抠图或使用色块遮罩；
- 允许背景降低 10–25% 饱和度，使人物和标题建立层级；
- 同一专题使用一致的裁切逻辑，不逐张随意处理；
- 需为桌面、平板和移动端分别指定焦点与安全区。

**C. 数据缩略图**

- 统一比例和对齐方式；
- 避免复杂滤镜，选中态使用边框、编号和状态条；
- 原图不足时用低对比底色补齐，不拉伸；
- 评级、模型和角色信息放在图外或稳定信息带中。

#### 裁切纪律

- 优先保留脸、眼神、手部动作、角色标志物和叙事关系；
- 双人图不得裁断视线关系或让其中一人退化成无意义边角；
- 人物看向右侧时，右侧应保留一定呼吸空间，反之亦然；
- 图文压叠时，标题进入的是低信息区，不是人物高信息区；
- 同一画面不同时使用强模糊、强网点、强双色化和高对比文字。

### 20.5 线条、几何与符号语法

每种几何形状应有稳定语义。

| 视觉语法 | 建议语义 | 典型场景 |
|---|---|---|
| 1px 细线 | 对齐、分隔、测量 | 标题基线、元数据、表格 |
| 2px 实线 | 选中、重点边界 | 当前场景、当前角色 |
| 4px 信号条 | 状态和高优先级动作 | 运行、警告、失败 |
| 矩形/方框 | 档案、数据、稳定容器 | SceneCard、模型、历史 |
| 圆/圆弧 | 周期、生成、语音、时间 | 生成进度、TTS、Live2D 状态 |
| 单一斜线 | 转折、章节切换、方向 | 专题封面、页间过渡 |
| 点阵/十字 | 采样点、对齐点 | 构图辅助、对比视图 |

约束：

- 同一组件只使用一种主几何语法；
- 圆形不能成为所有按钮的默认造型；
- 斜切角仅用于章节、状态或主题包装，不用于所有卡片；
- 引线必须连接到有意义的目标；
- 警戒纹只用于真实风险、失败、限制和不可逆提示；
- 不使用官方阵营徽记、Rhodes Island 标记或近似商标。

### 20.6 留白与密度地图

留白是画面的主动部分，用于隔开叙事，而不是“没放内容的地方”。

建议为每个页面先画一张密度地图：

- **高密度区**：一个屏幕最多 1–2 处，放主体、主标题或核心操作；
- **中密度区**：放说明、卡片、筛选和元数据；
- **低密度区**：让视线停顿，承载微弱纹理或完全留空；
- 高密度区之间必须有清晰的低密度过渡。

页面密度建议：

| 页面 | 视觉策略 |
|---|---|
| 首页 / 专题 | 60–70% 安静背景，集中一个大焦点 |
| 灵感场景 / 作品册 | 中密度目录，靠分组与节奏而非大面积空白 |
| 绘制台 / 控制台 | 高信息密度，但模块边界明确、装饰极少 |
| 角色房间 | 人物周边留白较多，聊天和设置保持稳定 |
| 训练台 / 场景管理 | 接近技术手册，强调纵向流程与表格秩序 |

### 20.7 色彩构成

单张构图建议使用：

- **70–85% 中性色**：背景、文字、结构；
- **10–20% 页面主题色**：角色、专题或章节识别；
- **2–5% 信号色**：当前状态、主操作、警告。

进一步约束：

- 每张专题封面只确定一个主信号色；
- 档案蓝用于选择、索引和技术状态，不与粉色主操作争抢；
- 角色色用于角色身份和情绪，不扩散到全站基础控件；
- 红/黄只承担风险、失败、限制或需要确认的动作；
- 调色先在灰度状态验证层级，再恢复主题色；
- 深色与浅色主题应保持相同的对比关系，不只做颜色反相。

### 20.8 四套可复用构图配方

#### 配方 A：人物主视觉

适用：首页专题、角色章节、活动入口。

- 人物占宽 42–58%，落在一侧或中央偏置；
- Display 标题占另一侧 4–6 列；
- 一条稳定轴连接标题、日期和主操作；
- 背景只保留一个低对比水印或几何结构；
- 主按钮与正文落在稳定网格，不跟随人物越界。

#### 配方 B：物件标本板

适用：模型、LoRA、风格、道具、训练数据专题。

- 主物件或缩略图置于中性底板；
- 真实标签、版本、来源和参数通过引线标注；
- 一张板只突出一个主物件，其余作为比较样本；
- 图外说明大于图内注释，避免把关键信息做得过小。

#### 配方 C：接触印样 / 展览目录

适用：效果样张、审核候选、作品册批次。

- 图片使用严格统一的比例与编号；
- 选择、通过、淘汰等状态落在图外；
- 单页只有一个被放大的主样本；
- 列表区域保持平静，详情区域承担视觉高潮。

#### 配方 D：章节分隔页

适用：长页面分段、模式切换、故事与角色小节。

- 一个大号编号或短标题；
- 一句描述当前章节目标的中文；
- 一条横向/纵向轴线；
- 一个来自真实数据的状态或计数；
- 不放复杂交互，点击目标最多一个。

### 20.9 页面中的平面设计角色

#### 首页

把首页作为“当期绘境封面”，而不是功能卡片集合：

- 每期选一张真实作品或角色作为主视觉；
- 大标题、当期主题、最新作品数和继续创作入口组成封面；
- 功能入口退到第二屏，使用目录式编号；
- 不自动轮播，不让多个 banner 争夺注意力。

#### 灵感场景

使用“主题刊物目录”：

- 每组场景有章节带、短前言和编号范围；
- SceneCard 保持统一，不把每张卡都设计成独立海报；
- 当前精选场景可以使用一次跨栏放大；
- 筛选和搜索仍是标准工具组件。

#### 绘制台

使用“工作底稿 / 场记板”：

- 平面设计只进入页头、画布安全框、Prompt 结构预览和状态条；
- 参数表单不做海报化；
- 场景模式保持低认知负担；
- 生成、队列、恢复和配音始终可见。

#### 角色房间

使用“人物通信页 / 私人档案页”：

- 角色舞台是主视觉，聊天是稳定阅读列；
- 日期、会话段落和 Voice 状态形成边缘索引；
- Live2D 启用前不使用大贴图作背景；
- 不用军事警戒纹破坏亲密氛围。

#### 效果样张与作品册

使用“展览目录 / 接触印样”：

- 批次、模型、角色和审核状态形成真实 caption；
- 图片之间保持足够留白；
- 详情查看保持作品原色；
- 对比图使用同一裁切和同一尺度。

#### 训练台、控制面板、场景管理

使用“技术手册 / 维护记录”：

- 结构、编号、步骤和日志构成主要平面语言；
- 允许高密度，但不用巨大标题抢夺操作注意力；
- 只有章节页和空状态使用较强平面编排；
- 风险视觉严格对应真实风险。

### 20.10 响应式平面编排

移动端不是把桌面海报等比缩小。

- 将桌面横向人物主视觉改为上下叠放；
- Display 标题完整显示，取消会导致误读的裁切；
- 隐藏背景大字、远端索引、长引线和装饰坐标；
- 主题图使用单独的移动端焦点位置；
- 元数据从散点标注收束为一条或两条 caption；
- 保留主内容、主操作和状态，不保留装饰性复杂度；
- 任何出血元素不得制造横向滚动。

建议至少验证以下宽度：

- 1920px：检查留白是否失控；
- 1440px：桌面主设计基线；
- 1280px：检查 12 列压缩后的稳定性；
- 768px：平板重组；
- 390px：移动端主基线。

## 21. 平面资产模板与落地工作流

### 21.1 先建立六类模板

不要一开始逐页自由发挥。先建立可复用的内容槽位和安全区：

1. **首页主视觉模板**：主题图、中文标题、短句、日期/状态、主操作；
2. **场景章节封面**：章节号、场景组名称、角色/风格、样张、数量；
3. **角色档案封面**：角色图、姓名、会话状态、Voice/Live2D 状态；
4. **作品批次封面**：主样本、批次号、模型、时间、作品数量；
5. **专题横幅**：主题图、标题、说明、进入动作；
6. **空状态版式**：一幅轻量插图/符号、一句状态、一项下一步动作。

每个模板都必须记录：

- 必填与可选内容；
- 桌面和移动安全区；
- 允许的标题长度；
- 图片焦点位置；
- 明暗主题版本；
- 无图时的退化方案；
- 屏幕阅读器中的语义顺序。

### 21.2 建议的组件原语

后续实现时可先创建少量无业务状态的视觉组件，避免在每个页面复制装饰：

- `GraphicSheet`：控制专题背景、裁切和安全区；
- `GraphicTitle`：控制 Display 标题、完整语义标题和编号；
- `GraphicAxis`：控制有意义的主轴、刻度和对齐；
- `GraphicCaption`：展示真实来源、模型、seed、日期与状态；
- `GraphicFigure`：控制图像焦点、移动端裁切和遮罩；
- `GraphicWatermark`：只接受当前对象的真实标题或编号；
- `GraphicSignal`：统一运行、成功、警告和失败状态。

实现约束：

- 组件只提供视觉骨架，不拥有业务数据和生命周期；
- 装饰尽量由 CSS 伪元素完成；
- 所有可见文本来自真实数据或显式文案；
- 同一装饰结构不得在 DOM 中重复生成大量节点；
- 默认支持 `prefers-reduced-motion` 和 `prefers-reduced-transparency`。

### 21.3 设计生产流程

每个专题或关键页面按以下顺序设计：

1. **写一句视觉命题**  
   例如：“这是一份关于夜间城市约会的私人档案”，而不是“做成明日方舟风”。

2. **列内容优先级**  
   主体、标题、主操作、说明、证据、装饰依次排序。

3. **做灰度缩略构图**  
   先用黑白方块验证焦点、留白与阅读方向，不急着选颜色。

4. **套入网格**  
   确定主轴、文本列、图像边界和安全区。

5. **建立尺度冲突**  
   只选择一个 Display 元素，与正文和元数据形成巨细对比。

6. **添加真实证据层**  
   放入项目真实的角色、场景、模型、时间、评级或生成状态。

7. **确定主题色与材质**  
   一张构图一个信号色，一种主纹理。

8. **制作响应式变体**  
   重新编排，不做等比缩放。

9. **回到真实内容验证**  
   使用长标题、无图、不同画幅、R18 模糊图和极端数据测试。

10. **进入组件系统**  
    只有至少两个页面验证可复用后，才抽象为公共组件。

### 21.4 平面设计 QA

每个重要版式需通过：

#### 远观测试

- 缩小到 25% 后，是否仍能看到唯一主焦点；
- 模糊观看时，视觉顺序是否为主体 → 标题 → 主操作；
- 是否存在两个同等强烈的高对比区互相竞争。

#### 灰度测试

- 移除颜色后，层级是否仍成立；
- 主操作是否仍可被识别；
- 状态是否不只依赖颜色。

#### 内容测试

- 标题变长 50% 是否破版；
- 没有人物图时是否有合理退化；
- 1:1、4:5、16:9 图像是否都能安全裁切；
- 原图查看是否保持未处理状态；
- R18 模糊遮罩是否仍有效。

#### 任务测试

- 新用户能否在 5 秒内找到主要动作；
- 装饰是否遮挡生成、队列、恢复、配音或保存；
- 移动端是否没有横向滚动；
- 键盘焦点是否不进入装饰层；
- 减少动效/透明度偏好是否生效。

#### 原创性测试

- 去掉项目名后，是否仍像“绫季绘境”而不是官方活动页；
- 是否使用了官方 Logo、徽记、活动标题字或高度近似图标；
- 是否存在只为模仿而添加的伪英文、伪坐标、伪警报；
- 所有装饰是否能由项目内容或页面任务解释。

### 21.5 本专项的第一批原型

在原有三个功能原型之外，增加两张纯平面原型：

1. **首页当期封面**
   - 使用一张现有作品；
   - 验证人物主视觉配方、巨细文字、留白和主操作；
   - 同时完成 1440px 与 390px 版本。

2. **场景专题章节页**
   - 使用一个真实场景组和 3–6 张样张；
   - 验证章节封面、接触印样、编号和审核状态；
   - 确认平面包装不会改变样张本身。

如果这两张原型与绘制台、角色房间原型能共享同一套 Token，却呈现不同的内容气质，说明平面系统具有延展性；如果所有页面都像同一张活动海报，则应减少主题装饰并加强功能层差异。

## 22. 官网专项研究：品牌门户如何像一本可操作的杂志

> 调研快照：2026-07-30。参考 [《明日方舟》官方网站](https://ak.hypergryph.com/)。

《明日方舟》官网不是把新闻、角色、世界观和下载入口简单堆成普通游戏官网。其信息结构更接近一组可以操作的全屏杂志跨页：每一屏拥有明确主题、单独构图和独立焦点，但始终由固定导航、章节编号、滚动提示和统一青蓝信号色串联。

当前官网可读结构本身已经暴露出这套平面逻辑：

- 首页以 `BREAKING NEWS`、日期和单条重点情报建立第一叙事层；
- 情报区将“最新 / 公告 / 活动 / 新闻”作为明确频道；
- 干员区使用 `PROFILE / CHARACTER VOICE` 和人物信息组织角色；
- 世界观区以 `ORIGINIUMS / ORIGINIUM ARTS / REUNION / INFECTED / NOMADIC CITY / RHODES ISLAND` 形成术语索引；
- 媒体区使用 `MONSTER SIREN / GALLERY / OPERATOR / VIDEO / ABOUT TERRA` 作为内容入口；
- 页面以 `00 // 00 / 05`、`SCROLL`、`READ MORE` 等固定微文案标记浏览位置和动作。

这说明官网的英文、编号和技术感文本并非随机装饰，而是分别承担：频道名、对象类型、浏览进度、动作提示和品牌地址。

### 22.1 官网的五个关键方法

#### 方法一：一屏一命题

每个全屏段落只回答一个问题：

- 现在最重要的消息是什么；
- 这个人物是谁；
- 这个世界有哪些核心概念；
- 还有哪些内容可以继续探索。

它避免在第一屏同时塞入所有功能，也避免让每个模块拥有同等视觉重量。

对本项目的启发：

- 首页首屏只负责“当前创作主题 + 继续创作”；
- 第二屏再展示最近作品或场景；
- 第三屏再进入角色、模型和其他工具；
- 不把十几个路由入口全部做成首屏等权卡片。

#### 方法二：固定框架托住变化内容

官网的章节内容变化很大，但导航、索引、滚动方向、固定文字和信号色保持稳定。视觉变化发生在“展览内容”中，而不是每到一屏就重做整套 UI。

本项目应建立：

- 固定的侧栏 / 顶栏；
- 固定的页面编号位置；
- 固定的标题 kicker 与主标题关系；
- 固定的状态与主操作位置；
- 允许变化的主视觉、主题色、纹理和展示字体。

#### 方法三：人物不是卡片内容，而是空间主体

角色页让人物立绘参与整屏构图，文字围绕人物建立档案关系，而不是把立绘塞进一个有阴影的圆角卡片。

用于角色房间时：

- 舞台中的角色保持大尺度和明确剪影；
- 姓名、Voice、当前服装和会话状态使用边缘档案排版；
- 聊天与设置仍用稳定容器，不压在人物脸和身体上；
- Live2D 未启用时使用轻量占位，不提前下载大贴图。

#### 方法四：章节编号把滚动变成叙事

`00 // 00 / 05` 一类索引让用户知道自己不只是“往下滚”，而是在穿过有限章节。

本项目可将它转译为真实进度：

- 首页：`01 / 04 当前创作`；
- 场景：`SCENE 08 / 30`；
- 作品批次：`PLATE 03 / 12`；
- 绘制流程：`STEP 02 / 04`；
- 角色空间：`SESSION 06`。

编号必须来自真实数据，不固定伪造一个看似复杂的分母。

#### 方法五：一个信号色贯穿全站

官网 CSS 中黑白灰占主导，亮青蓝被集中用于选中、按钮、滚动条和关键文字。其价值是把“品牌记忆色”与“交互反馈色”合并，降低视觉噪声。

本项目不应直接复制同一青色，而应保留现有配色职责：

- 档案蓝：选择、索引、运行与技术状态；
- 绫季粉：主要创作动作与角色温度；
- 角色色：身份与情绪；
- 红 / 黄：真实风险与警告。

一屏只允许一个信号色占据最高注意力。

### 22.2 官网式页面骨架

可抽象成以下结构：

```text
┌────────────────────────────────────────────────────────────┐
│ FIXED BRAND / SECTION                         01 / 05       │
│                                                            │
│        [大尺度人物 / CG / 主题物件]                         │
│                                      KICKER                │
│                                      中文主标题             │
│                                      一段简短说明           │
│                                      [唯一主操作]           │
│                                                            │
│ SCROLL / NEXT                                  META / DATE │
└────────────────────────────────────────────────────────────┘
```

注意：这只适合首页、专题、角色档案和章节页。绘制台、训练台、控制面板等生产页面不应强制使用全屏跨页。

### 22.3 可以学习与不应照搬的部分

可以学习：

- 一屏一主题；
- 固定框架 + 变化内容；
- 人物参与空间构图；
- 真实章节编号；
- 双语承担信息分层；
- 极少信号色；
- 将滚动设计成章节切换。

不应照搬：

- 官方 Logo、罗德岛字样和世界观术语；
- 完全相同的青色、字体和角标；
- 面向营销官网的强制全屏分页；
- 过长加载开场；
- 让常用本地工具为了“沉浸”增加操作步骤；
- 在移动端保留复杂的悬浮边缘文字。

## 23. 塞壬唱片专项研究：用统一外框容纳极端多样的封面

> 调研快照：2026-07-30。参考 [塞壬唱片官网](https://monster-siren.hypergryph.com/)、[专辑陈列](https://monster-siren.hypergryph.com/music/) 与 [专辑详情示例](https://monster-siren.hypergryph.com/music/880376)。

塞壬唱片最值得学习的地方，是它把游戏音乐包装成一个真实存在于世界观中的唱片公司。首页文案 `A WORLD FAMILIARLY UNKNOWN`、关于页的唱片公司叙事、数百张风格差异巨大的专辑封面、播放列表和常驻播放器，共同构成了一套“虚构机构 + 真实内容服务”的品牌体验。

这比简单做一个音乐列表更高明：用户看到的不是功能集合，而是一家持续发行作品的机构。

### 23.1 两层品牌系统

塞壬唱片可以被理解成两层：

1. **唱片公司外框**
   - 深色背景；
   - 中性灰文字；
   - 浅青信号色；
   - 统一的搜索、导航、列表、播放和过渡；
   - 克制、冷静、稳定。

2. **每张发行物的世界**
   - 每张封面拥有自己的插画、字体、配色和题材；
   - 单曲、OST、现场 EP 可以完全不同；
   - 进入详情页后，当前专辑成为唯一视觉中心。

这套原则非常适合 AI-CG-Studio：**工具外框统一，作品专题自由。**

- 应用壳、按钮、表单和状态保持统一；
- 每个角色、场景组、作品批次可以拥有独立封面；
- 变化发生在内容资产和专题 Token，不发生在基础交互规则。

### 23.2 专辑陈列不是普通卡片网格

当前官网的专辑陈列同时提供搜索、封面、名称和艺人信息。官方样式中，列表项以正方形封面配合较大的标题与较轻的艺人信息；条目通过横向进入动画建立浏览节奏。封面保持完整，外层 UI 没有用统一滤镜抹掉差异。

转译到作品册：

- 每个作品批次像一张“发行物”；
- 正方形封面由该批次的代表作生成；
- 标题下方显示角色、模型、场景和日期；
- 列表可搜索角色、场景、模型、评级和 Prompt 标签；
- 进入批次详情后再显示完整画幅，不把所有信息压在封面上；
- 不需要把网站真的叫唱片公司，也不需要模仿唱片术语到影响理解。

建议项目内使用更贴合自身的名称：

- `EDITION`：一次作品编选；
- `PLATE`：一组可审核样张；
- `SESSION`：一次角色会话；
- `SCENE BOOK`：一个场景专题；
- `ARCHIVE`：完整作品档案。

中文必须同步出现，例如 `EDITION / 作品编选`，避免用户猜测英文含义。

### 23.3 常驻播放器带来的“连续状态”启发

塞壬唱片的播放器固定在页面底部，包含封面、曲目信息和播放控制。页面切换时，音乐不是一次性页面内容，而是跨页面持续存在的会话状态。

本项目不需要照搬音乐播放器，但可以学习这种连续状态表达：

- 出图队列在相关页面间保持可见；
- 当前生成任务有缩略图、进度、模型和取消/查看动作；
- Voice 合成有当前句、角色、进度和播放状态；
- 长任务不因用户切换到作品册而“消失”；
- 状态条保持紧凑，不遮挡主内容。

可以设计一个统一的 `ActivityDock / 活动坞`：

```text
┌────────────────────────────────────────────────────────────┐
│ [缩略图] 正在生成 · 夜间街道     62%    SDXL   [查看] [×] │
└────────────────────────────────────────────────────────────┘
```

它只聚合现有的生成、队列和 Voice 连续状态，不重新拥有其业务生命周期。

### 23.4 把“加载”变成品牌仪式，但保持短促

塞壬唱片首页用 `WELCOME TO 塞壬唱片`、品牌口号和百分比加载构成进入仪式；《明日方舟》官网也显示加载进度。它们适合大型品牌站，因为首屏本身就是体验的一部分。

本地工具的正确转译：

- 首次进入可使用 300–600ms 的轻量标题组装；
- 数据真的需要加载时才显示百分比或阶段；
- 已缓存页面不重复播放完整开场；
- 生产页禁止用品牌动画阻塞操作；
- `prefers-reduced-motion` 下直接显示最终状态；
- 不伪造加载百分比。

### 23.5 封面生态：统一尺寸，不统一风格

塞壬唱片长期积累的优势来自“系列中的差异”。大量封面保持正方形载体与统一浏览行为，但插画、摄影、几何、文字、古典、实验和流行语言都可以出现。

项目应建立自己的封面生态：

| 封面类型 | 主体 | 平面语言 | 适用对象 |
|---|---|---|---|
| Character Edition | 单角色 | 大头像/半身、角色色、姓名索引 | 角色作品集 |
| Scene Book | 场景关系 | 宽景裁切、章节号、短叙事 | 场景组 |
| Model Plate | 视觉差异 | 接触印样、参数、版本 | 模型/LoRA 对比 |
| Story Session | 人物与对白 | 留白、时间、通信标记 | 角色会话 |
| Audit Archive | 审核证据 | 网格、编号、通过/淘汰状态 | 样张审核 |
| Voice Record | 角色与声波 | 圆形节奏、字幕、Voice 状态 | 配音片段 |

共同约束：

- 作品封面基准使用 1:1，同时提供 16:9 章节裁切；
- 统一安全区、标题槽位、编号与元数据位置；
- 封面可使用不同主题字体，但 UI 文本仍用全站字体；
- 每张封面只使用一个主图形母题；
- 详情页必须能回到未经处理的原图；
- R18 封面仍使用模糊遮罩，不因封面设计绕过规则。

### 23.6 搜索与目录也是平面构成

塞壬唱片把搜索结果分为专辑与资讯，标题、分隔线和细小斑马纹共同组织结果。这里的平面元素确实在表达类别与层级，而非纯装饰。

项目可应用到全局搜索：

- `SCENE / 场景`；
- `CHARACTER / 角色`；
- `WORK / 作品`；
- `MODEL / 模型`；
- `SESSION / 会话`。

每类结果共用相同搜索交互，但拥有不同的缩略图比例和元数据。分类标题、数量和分隔线必须真实反映结果，不添加无意义警戒条。

## 24. 两个官网合并后的原创设计策略

《明日方舟》官网提供“章节式品牌门户”，塞壬唱片提供“统一机构外框下的多样内容目录”。AI-CG-Studio 最适合吸收二者的交集，而不是复制任何一方：

> **把整个网站设计成一间持续编辑、生成、审核并出版私人 CG 的数字工作室。**

### 24.1 三层视觉架构

#### 第一层：Studio Shell / 工作室外框

全站固定：

- 导航；
- 基础色与字体；
- 表单、按钮、弹层；
- 状态语义；
- ActivityDock；
- 响应式与无障碍规则。

它必须安静、可靠，不随专题变形。

#### 第二层：Archive Chapter / 档案章节

页面级变化：

- 页面编号；
- 章节标题；
- 主视觉；
- 当前主题色；
- 一种几何母题；
- 一种材质；
- 页面进入与章节切换动效。

用于首页、场景、角色、作品册和模型专题。

#### 第三层：Edition / 作品编选

内容级自由：

- 每个作品批次的封面；
- 每个角色的色彩与字体气质；
- 每个场景的图像裁切；
- 每个模型对比的展示规则；
- 每次审核的状态与说明。

这一层可以非常多样，但不能改变全站基础交互。

### 24.2 专题 Token

在现有全局 Token 之上，只允许专题覆盖少量变量：

```css
.archive-chapter {
  --chapter-accent: var(--archive-blue);
  --chapter-ink: var(--text-primary);
  --chapter-paper: var(--surface-1);
  --chapter-display-font: var(--font-display);
  --chapter-figure-position: 50% 50%;
  --chapter-texture-opacity: 0.035;
}
```

允许覆盖：

- 一个强调色；
- Display 字体；
- 主图焦点；
- 背景材质透明度；
- 章节装饰图形。

禁止覆盖：

- 成功、警告、失败色；
- 正文字体和字号下限；
- 表单、弹层与焦点样式；
- R18 遮罩；
- 触控面积；
- 生成、队列、恢复与配音入口的可见性。

### 24.3 页面类型与参考来源映射

| 项目页面 | 主要学习对象 | 采用的平面方法 |
|---|---|---|
| 首页 | 明日方舟官网 | 全屏章节、重点情报、固定索引 |
| 灵感场景 | 官网世界观 + 塞壬目录 | 术语索引、章节封面、场景编选 |
| 角色房间 | 官网干员页 | 人物空间主体、档案边栏、Voice 信息 |
| 作品册 | 塞壬专辑陈列 | 封面生态、搜索、编选详情 |
| 效果样张 | 塞壬目录 + 技术标本板 | 接触印样、真实 caption、对比焦点 |
| 模型 / LoRA | 塞壬发行物 | 每个模型一张发行封面 + 版本信息 |
| 绘制台 | 本项目现有工作流 | 只吸收状态条、编号和画布构图线 |
| 训练台 / 控制面板 | 本项目技术手册语法 | 高密度流程、日志、风险状态 |

### 24.4 站内“季度视觉”机制

为了获得塞壬唱片那种持续出版感，可以建立轻量的季度/专题机制，而不更改业务数据：

- 首页选择一个 `Featured Edition / 当期编选`；
- 从现有作品中选一张主图；
- 配置一个主题标题、短句和强调色；
- 场景页展示关联场景组；
- 作品册展示关联批次；
- 到期后进入专题档案，不删除旧视觉。

配置结构示意：

```ts
interface FeaturedEdition {
  id: string
  title: string
  subtitle?: string
  coverImageId: string
  sceneIds: string[]
  workIds: string[]
  accent: string
  focalPoint: { x: number; y: number }
  startsAt?: string
  endsAt?: string
}
```

该机制只负责内容编选与视觉包装，不复制作品、不改变图片审核状态，也不承担生成任务。

### 24.5 动效分级

将官网动效压缩为适合工具站的三级系统：

| 级别 | 时长 | 用途 | 示例 |
|---|---:|---|---|
| Micro | 120–200ms | 操作反馈 | hover、选中、按钮状态 |
| Section | 240–420ms | 内容关系变化 | 场景详情、封面展开、章节切换 |
| Ritual | 300–600ms | 极少数品牌时刻 | 首次进入首页、当期封面出现 |

约束：

- 生产页只用 Micro 和必要的 Section；
- Ritual 不阻塞点击；
- 列表进入动画最多错开 6 项，之后同时出现；
- 长列表不逐项播放；
- 运行中的生成和 Voice 使用真实进度，不用无限装饰动画替代状态；
- 减少动效模式下全部退化为淡入或直接出现。

### 24.6 新增设计验收题

设计评审时增加以下问题：

1. 去掉所有装饰后，页面任务是否仍清晰？
2. 去掉所有图片后，信息架构是否仍成立？
3. 换成完全不同风格的作品封面后，外层 UI 是否仍稳定？
4. 页面英文是否都能解释为频道、类型、动作或真实数据？
5. 是否只有一个最高视觉焦点？
6. 是否把营销官网手法误用到了高频生产页面？
7. 当前专题色是否覆盖了警告、失败等功能色？
8. 章节编号和进度是否来自真实状态？
9. 移动端是否完成重新编排，而非桌面海报缩小？
10. 用户能否明确感到这是“绫季绘境的数字工作室”，而不是明日方舟仿站？

### 24.7 下一步原型优先级调整

结合本轮官网研究，原型顺序调整为：

1. **首页当期封面 + 章节滚动**：验证官网式门户骨架；
2. **作品册 Edition 目录 + 详情**：验证塞壬式统一外框与多样封面；
3. **灵感场景 Scene Book**：验证世界观索引和场景编选；
4. **绘制台状态条 + ActivityDock**：验证连续任务状态不干扰生产；
5. **角色房间档案舞台**：验证人物构图与亲密交互共存。

第一轮只做静态设计稿或独立原型，不立即改全站。首页和作品册两套原型同时成立后，再提炼公共组件与专题 Token。

## 25. 核心动效专项：语义粒子，而不是通用飘尘

用户特别指出的官网设定页粒子效果，应提升为本项目视觉升级的关键参考。

它高级的原因不只是“画面里有很多点”，而是粒子本身承担了内容表达：离散点先表现未知、数据或能量，再聚合成与当前设定有关的轮廓；切换条目时，同一组点重新组织成下一种形态。动画连接了“概念选择”和“概念显形”，因此既是氛围，也是信息反馈。

[《明日方舟》官网](https://ak.hypergryph.com/) 当前设定区仍以源石、源石技艺、整合运动、感染者、移动城邦与罗德岛等条目构成可切换的概念索引。第三方实现研究曾针对官网同类效果提取形状坐标，以 PixiJS 绘制点、让点从随机位置向目标坐标缓动；该研究可用于理解效果结构，但不能当作当前官网源码的官方说明：

- [PixiJS + GSAP 模拟明日方舟粒子动画](https://docs.ffffee.com/frontend/1128-Pixijs-gsap-learn.html)
- [PixiJS 官方 ParticleContainer 文档](https://pixijs.com/8.x/guides/components/scene-objects/particle-container)
- [GSAP 官方 easing 文档](https://gsap.com/docs/v3/Eases/)

### 25.1 动效的正确拆解

该类效果可以拆成六个同时工作的部分：

1. **点云素材**：每个主题对应一组目标坐标；
2. **离散初态**：粒子随机分布或保持上一个主题的形态；
3. **形态重组**：点向新坐标移动，形成可辨认轮廓；
4. **层次差异**：粒子在大小、亮度、透明度上有轻微差异；
5. **缓动曲线**：前段快速收拢，后段柔和落位，形成“凝聚”感；
6. **文本同步**：标题、说明、索引线与粒子在同一节奏中完成切换。

如果只做第一项和随机漂浮，就会变成常见“星空背景”；如果六项形成因果关系，才会产生设定页那种高级感。

### 25.2 项目的原创粒子母题

不能把官方阵营图标、源石轮廓或坐标数据搬进项目。AI-CG-Studio 应从自身内容生成形态：

| 主题 | 可用粒子轮廓 | 语义 |
|---|---|---|
| 灵感场景 | 城市天际线、房间窗框、海浪、雪线、花瓣轮廓 | 场景类别显形 |
| 角色档案 | 角色侧影、发饰、代表性道具的抽象轮廓 | 角色身份 |
| 绘制台 | 构图框、焦点十字、镜头视锥、分镜格 | 从意图到画面 |
| 作品册 | 相纸边框、装订线、页码轮廓 | 作品被归档 |
| 模型 / LoRA | 节点网络、权重曲线、对比矩阵 | 模型差异 |
| Voice | 声纹、圆形脉冲、字幕节奏线 | 声音正在形成 |

轮廓应保持抽象，不能尝试用低密度点云还原完整角色插画；粒子用于“识别符号”，真实作品仍由原图承担。

### 25.3 三态交互模型

#### Idle / 静息

- 粒子已形成当前主题轮廓；
- 只有 2–6px 的低频漂移；
- 少量粒子缓慢改变透明度；
- 不持续旋转整幅图，不制造屏保感。

#### Explore / 探索

- 指针靠近时，局部粒子产生轻微排斥或吸引；
- 影响半径建议 80–140px；
- 最大位移建议 6–18px；
- 指针移开后自然回到目标坐标；
- 文本和按钮本身不跟随鼠标漂移。

#### Transform / 切换

- 当前点云先短暂松动，再向新形态收拢；
- 总时长建议 900–1500ms；
- 前 15–25% 用于解除旧轮廓，后段完成新轮廓；
- 使用 `power3.out` / `power4.out` 一类明显减速的曲线；
- 标题可在点云形成 35–50% 时进入；
- 用户连续切换时重定向现有粒子，不创建一批新粒子叠加。

### 25.4 粒子视觉参数

建议初版参数：

| 参数 | 桌面基线 | 低性能 / 移动端 |
|---|---:|---:|
| 活跃粒子数 | 700–1200 | 160–420 |
| 粒子半径 | 0.75–1.5px | 1–1.5px |
| 主粒子占比 | 70–85% | 80–90% |
| 透明度 | 0.25–0.85 | 0.35–0.75 |
| 静息漂移 | 2–6px | 0–3px |
| 形变时长 | 900–1500ms | 500–900ms |
| 指针影响半径 | 80–140px | 关闭 |
| DPR 上限 | 1.5–2 | 1–1.5 |

色彩结构：

- 75–85% 使用中性灰白；
- 10–20% 使用更暗的深灰点，增加空间层次；
- 2–5% 使用当前章节信号色；
- 不做整屏高亮彩色粒子；
- 亮点不能出现在正文后方形成闪烁干扰。

### 25.5 高级感来自分层，而不是粒子数量

推荐的画面层级：

```text
Layer 0  深色或浅灰中性背景
Layer 1  极弱网格 / 纸张纹理
Layer 2  远景微尘（低密度、低对比）
Layer 3  语义点云（主要形态）
Layer 4  少量结构线 / 章节轴 / 坐标框
Layer 5  标题、说明与交互
Layer 6  焦点、状态与无障碍文本
```

关键关系：

- 远景微尘永远不形成主视觉；
- 语义点云是唯一高密度粒子层；
- 结构线与点云对齐，而不是随机穿过；
- 文本层不使用强混合模式；
- 粒子可被主图或标题遮挡，制造前后空间；
- 最亮粒子不超过标题和主要操作的视觉权重。

### 25.6 适合与不适合持续运行的页面

#### 强使用

- **首页当期封面**：一个主题轮廓，在进入时完成一次聚合；
- **灵感场景**：切换场景类别时在原创轮廓间重组；
- **场景专题页**：作为章节封面的主视觉；
- **模型专题页**：用点阵表现模型结构或版本差异。

#### 轻使用

- **作品册**：只在批次封面展开时出现少量粒子装订线；
- **角色房间**：仅在角色切换或 Voice 状态中使用局部点云；
- **空状态**：用静态点云轮廓，不持续动画。

#### 禁止常驻

- 绘制台参数区；
- Prompt 编辑器；
- 生成队列；
- 训练日志；
- 控制面板；
- 弹层、表单和错误恢复面板。

这些区域可以在完成、失败或切换时使用一次性微动效，但不能有持续粒子背景。

## 26. 粒子系统技术方案

### 26.1 首选：原生 Canvas 2D

第一版建议用原生 Canvas 2D 完成 700–1200 个简单圆点的坐标插值，不立即引入大型 3D 引擎。

理由：

- 效果本质是二维点云变形；
- 项目已有 Vue 3 / Vite，可独立懒加载一个组件；
- 简单圆点可以批量绘制；
- 容易暂停、降级和控制 DPR；
- 不会让所有页面承担额外运行时。

当 Canvas 2D 在目标设备上无法稳定满足效果，或后续需要大量精灵、滤镜和更高粒子数量时，再评估 PixiJS。PixiJS 必须按路由动态加载，不能进入全站公共首包。

### 26.2 组件边界

建议组件：

```text
src/components/visual/
  SemanticParticleField.vue
  ParticleFallback.vue
src/composables/
  useParticleField.ts
src/utils/particle/
  interpolate.ts
  pointerForce.ts
  qualityTier.ts
src/assets/particle-shapes/
  scene-city.json
  scene-room.json
  scene-sea.json
```

所有权：

- `SemanticParticleField.vue`：Canvas、尺寸、生命周期和渲染；
- `useParticleField.ts`：主题切换、暂停、可见性与减少动效；
- `interpolate.ts`：坐标重组和缓动；
- `pointerForce.ts`：局部指针影响；
- `qualityTier.ts`：根据设备与实时帧率选择粒子数量；
- 页面只传 `shapeId`、强调色和激活状态，不操作渲染循环。

粒子系统不得拥有场景数据加载、生成任务、角色状态或 Live2D 生命周期。

### 26.3 坐标素材生产

坐标形态应离线生成，运行时只读取紧凑数据。

流程：

1. 用原创 SVG 或高对比黑白蒙版绘制轮廓；
2. 将蒙版缩小到 256–512px 的采样空间；
3. 按 alpha / 亮度阈值取得候选点；
4. 使用规则网格加少量抖动，或 Poisson-like 间距避免结团；
5. 按轮廓重要度保留 700–1200 点；
6. 归一化为 `0–1` 坐标；
7. 生成静态 fallback 图；
8. 人工检查轮廓在不同背景与尺寸下是否仍可辨认。

示意数据：

```ts
interface ParticleShape {
  id: string
  viewBox: [number, number]
  points: Array<[number, number, number?]>
  fallback: string
}
```

第三个值可表示亮度层级，不携带虚构物理参数。

### 26.4 点与点如何重组

为了避免切换时出现大量粒子横穿整个画面，不按数组原始顺序硬配对。建议：

- 先将新旧点按网格区块或极坐标排序；
- 优先连接相邻区域的点；
- 粒子数不同时复用已有点，多出的点从最近邻或边缘淡入；
- 减少的点向最近轮廓点回收并淡出；
- 每个点加入极小的时长偏差，但不做夸张随机延迟；
- 形态切换期间保留用户的指针影响，但将强度降到 20–35%。

这会让形变像“物质重组”，而不是漫天飞线。

### 26.5 渲染循环

渲染只在必要时运行：

- 元素进入视口后启动；
- 离开视口后停止 `requestAnimationFrame`；
- `document.hidden` 时停止；
- 静息稳定数秒后可降至 24–30fps；
- 指针进入或开始变形时恢复 60fps；
- 路由卸载时取消帧、事件和观察器；
- 画布尺寸变化做 100–150ms 合并处理，不每次 resize 立即重建点云。

### 26.6 性能预算

初版预算：

- 粒子代码独立 chunk，Canvas 版本目标不超过 30KB gzip；
- 单个形态数据目标不超过 20KB gzip；
- 单页最多预载 3 个形态，其余按需读取；
- 默认粒子数不超过 1200；
- DPR 最高 2，4K 屏优先扩大逻辑尺寸而非无限提升像素密度；
- 动效活跃时目标 55–60fps；
- 连续 20 帧低于 45fps 时自动降低一个质量档；
- 连续 20 帧低于 30fps 时切换静态 fallback；
- 不与 Live2D、大图解码或生成结果批量加载同时抢占主线程。

质量档建议：

| 档位 | 粒子数 | 指针交互 | 漂移 | DPR |
|---|---:|---|---|---:|
| High | 900–1200 | 完整 | 完整 | 1.5–2 |
| Medium | 500–800 | 减弱 | 减弱 | 1–1.5 |
| Low | 160–360 | 关闭 | 极弱 | 1 |
| Static | 0 | 关闭 | 关闭 | 静态图 |

### 26.7 无障碍与降级

- `prefers-reduced-motion: reduce`：直接显示最终点云或静态 SVG，不播放重组；
- `prefers-reduced-transparency: reduce`：移除混合模式与远景微尘，提高轮廓对比；
- 粒子 Canvas 标记 `aria-hidden="true"`；
- 当前主题名称由真实标题元素表达；
- 粒子不可成为唯一的选中、加载或成功信号；
- 键盘操作触发的主题切换与鼠标触发完全等价；
- Canvas 初始化失败时，页面任务和内容仍完整可用。

## 27. 粒子动效原型任务书

### 27.1 原型目标

先做一个独立实验页，不接入正式业务：

- 左侧 4 个原创场景条目；
- 右侧一块语义粒子画布；
- 粒子在城市、室内、海边、雪景四个轮廓间重组；
- 标题、短描述和编号同步切换；
- 支持指针轻微排斥；
- 支持减少动效、低性能降级和 390px 移动端。

### 27.2 验收标准

视觉：

- 静止截图也有明确构图，不依赖动起来才好看；
- 四个轮廓在 1 秒内可以被辨认；
- 粒子重组时没有明显长距离交叉乱线；
- 章节色只点亮极少数粒子；
- 文字始终比粒子更清晰。

交互：

- 切换后 100ms 内开始产生反馈；
- 连续快速切换不会叠加多套动画；
- 指针交互柔和，不形成磁铁玩具感；
- 键盘、触摸与鼠标均可切换主题；
- 动效不阻塞条目点击。

性能：

- 普通桌面保持目标帧率；
- 4K 屏不按像素面积无限增加粒子；
- 离开视口和切换标签页后停止渲染；
- 移动端无横向滚动；
- 静态 fallback 可在脚本异常时显示。

### 27.3 接入顺序

原型通过后按以下顺序接入：

1. 灵感场景页专题头部；
2. 首页当期封面；
3. 模型 / LoRA 专题详情；
4. 作品册空状态或批次封面；
5. Voice 局部声纹。

每接入一个页面都重新验证信息可读性与帧率，不直接把粒子组件铺到全站。
